# 可达性地图引导抓取位姿修正：调研与接入判断

日期：2026 年 11 月 21 日。本轮完成论文阅读、现有地图接口检查与已保存七轴失败记录复核；新增规划查询 0 次，新增仿真抓取 0 次。头部感知与语义分割接入暂缓，本轮优先研究抓取位姿修正。

后续执行说明：本段数字描述调研阶段；用户随后已授权离线验证，原始调研结论保留。2026 年 11 月 21 日进一步确认，地图模块的目的限定为完整抓取位姿的可达性：以 IK 关节见证、独立 FK 与限位核验作为输出证据。碰撞、路径和实际夹持分别作为下游检查，不把其通过率合并为运动学可达率。当前执行器已有的完整离线规划 `success` 字段保留原义，后续用派生证据另列主要指标。

## 调研结论

这个方向有直接的研究依据，值得验证。建议首版采用“可达性地图提供搜索方向和关节见证＋保留夹持几何的局部位姿搜索＋原场景 IK 与路径检查”，先验证不训练的修正器。

本次要改变的是抓取终点 G 的位置或朝向，产生 G′。此前地图初值、候选排序和预抓取距离 H 的研究都保持 G 不变，不能用其结果推断局部 G 修正有效或无效。当前还没有 ARX 实测证据证明修正能提高抓取成功率。

首版优先研究绕实际双指夹持轴的接近角度变化，再考虑进入深度和沿物体表面的有限抓点移动。任一变化都要重新检查实际夹爪包络、目标夹持关系与完整路径。单纯向地图高密度区域平移，可能把夹爪移到物体旁边。

## 相关论文提供了什么

| 工作 | 已核查的方法 | 对本项目的参考价值与边界 |
| --- | --- | --- |
| [Workspace Aware Online Grasp Planning，IROS 2018](https://crlab.cs.columbia.edu/reachabilityawaregrasping/) | 将离线可达空间转为 SDF，把可达性与抓取稳定性共同纳入在线搜索能量；见[论文第 III 节](https://www.cs.columbia.edu/~allen/PAPERS/ireti_iros_2018.pdf) | 最直接支持“地图参与抓取搜索”；本地正向采样图仍需处理未知区域，不能原样当作稠密可达／不可达 SDF |
| [GOMP，ICRA 2020](https://berkeleyautomation.github.io/GOMP/) | 在理想平行夹爪的同一对接触点附近，利用绕夹持轴的转动自由度，联合优化抓取和运动；见[论文开篇与方法](https://goldberg.berkeley.edu/pubs/2020-ICRA-Ichnowski-GOMP-Grasp_Optimized_Motion_Planning.pdf) | 适合作为首版局部朝向修正依据；论文主要优化运动时间，ARX 有限指腹与掌部仍需额外几何复核 |
| [Learning to Generate 6-DoF Grasp Poses with Reachability Awareness，ICRA 2020](https://arxiv.org/abs/1910.06404) | 从仿真经验学习抓取生成与可达性预测 | 说明学习路线已有先例；它需要合适数据，不能把我们未覆盖的地图格直接作为不可达负例 |
| [Arm-Aware Guided Dexterous Grasp Generation](https://arm-aware-dexgrasp.github.io/) | 在推理时用机械臂运动学和环境约束引导原有抓取模型 | 可作为后续生成器内部引导的参考；面向灵巧手，当前项目页的代码入口仍标注即将公开，首版不依赖它 |
| [Steer2Grasp，2026 年预印本](https://arxiv.org/html/2609.33546v1) | 在扩散过程中按可达性和碰撞反馈重采样候选，并对接近可行的样本做局部修正 | 值得作为后续方案：局部邻域无法覆盖另一种有效抓法时，可以改变生成分布；首版先保留生成器接口不动 |

2018 年工作的[官方代码](https://github.com/CRLab/reachability_aware_grasping_ws)依赖 ROS Indigo 与 GraspIt!，适合借鉴目标函数和数据表示，工程上直接接入当前 ManiSkill／cuRobo 的代价较高。GOMP 的接触轴自由度可以单独借鉴，无需整体替换当前规划器。

以上为方法参考，不沿用其他机器人的成功率作为 ARX 预期。特别是 Steer2Grasp 的可达判定容差为 1 cm／2°，主要保持指标与我们连续抬升保持的定义不同；ARX 继续使用本项目的原容差与物理成功判据。

## 现有地图能否直接使用

依据：[首版地图结果](结果说明.md)、本地查询接口 `工具/能力索引.py`、[前轮研究结果](../../实验/自动研究_20261120_01/最终报告.md)。

| 已有条件 | 对修正模块的含义 |
| --- | --- |
| 3267633 组静态有效关节见证，保存实际 FK 位姿 | 可以提供邻近完整位姿及不同关节分支的建议，适合常驻查询 |
| 精细位置格为 2 cm，另有离散朝向格 | 不足以直接描述毫米级抓取容差；修正候选附近需要局部细化与精确 IK |
| 困难查询最佳种子误差中位数为 16.4 mm／42.7° | 样本总量多不等于指定位置与朝向的局部覆盖充分 |
| 数据在 body4 坐标系，原静态检查采用约 22 cm 升降 | 升降与桌面关系变化后，旧静态碰撞通过标签需要重新核验 |
| 地图未包含每个当前杂物场景 | 地图命中后仍需检查当前桌面、目标、挡物及完整机器人路径 |
| 地图没有实际接触、摩擦保持与抓取成功标签 | 地图不能独立判断修正后的夹持质量 |

建议将“右臂相对 body4 的运动学见证”和“给定升降／场景下的碰撞有效性”分开。原六轴关节角与相对 FK 关系可作为七轴搜索的候选线索，再配合法定升降值核验；旧图已按原桌面关系筛掉部分构型，重用的见证库会有缺口，不能当作完整七轴地图。

第一阶段不把空白体素标成不可达，不直接对原始采样密度求梯度。位置距离、朝向距离、关节余量和查询误差分别保留，用作软搜索依据；可执行性仍由精确模型判定。

前轮开发集地图选 H 与直接短 H 搜索都为 10/12，留出都为 6/12；没有看到地图相对同类搜索的额外通过数。这次需要设置不使用地图的同预算局部位姿搜索，才能判断地图是否有独立贡献。

## 建议采用的首版方法

这是依据文献和本地接口提出的工程方案，尚未实现。

数据流：**合法抓取候选 G → 失败阶段定位 → 地图检索邻近位姿／关节见证 → 有夹持约束的局部 G′ 搜索 → 重新检查实际夹爪几何 → 七轴 IK、整机碰撞与完整路径 → 实际抓取。**

| 顺序 | 做法 | 需要核验的条件 |
| --- | --- | --- |
| 1 | 固定候选来源、原后处理与 TCP43，保留原 G 和原可执行候选 | 建立同一输入下的基线，避免因替换生成器、相机或候选数量而混淆收益 |
| 2 | 用当前测量的 body4 位姿转换 G，地图提供邻近朝向和多分支关节初值 | 记录平移／旋转误差及模型配置；未知只作未知 |
| 3 | 先绕实际双指夹持轴搜索接近角度 | 理想接触对尽量保持；有限指腹、掌部和相机支架可能改变包络，仍需重新检查 |
| 4 | 必要时再搜索进入深度和沿表面的有限抓点移动 | 范围依据物体尺寸、可见接触几何和实测指腹确定；不使用统一向下补压或向最近可达点吸附 |
| 5 | 复核抓取质量及规划 | 开口、双侧夹持证据、指腹覆盖、非接触部位碰撞；重新验证 G′、按同规则派生的 H、接近和抬升 |
| 6 | 对离线通过的方案执行独立物理验证 | 实际双指接触、动作收敛、禁止接触、至少 1 cm 抬升并连续保持 3 秒；记录恢复和退步 |

接触点存在遮挡、只有单侧可靠观测时，应记录几何证据不足，不能为了通过地图分数补出未经观察的理想接触。完整仿真网格可用于独立诊断与评价；若算法使用了它，必须单列为真值几何实验，不能混入单视角点云方案。

评分建议分两层：先以原几何和规划检查作为可执行条件，再在通过的建议中比较抓取质量、关节余量、修改幅度及运动成本。修正后若有可用的冻结抓取评分器，应对 G′重新评分；不能继承原 G 的分数并称为质量未变。实际保持能力最终由物理试验检验。

七轴先作为主体，底盘固定。预抓取规则、碰撞设置和成功判据在比较组之间一致；本轮不同时引入头部相机、语义分割或新的 H 搜索策略。

## 与 GraspGen 的接口需要明确

修正器位于抓取生成器之后，可以用已有缓存候选检验方法，再接入已登记的 GraspGen 路线。原始候选、评分及后处理来源始终保留；不退回未经原生后处理的数千个原始候选。

本机已核查到的是 GraspGenX 的 ARX 适配与权重。该适配中，生成器的 +X 为夹持方向，对应 ARX EEF 的 +Y；坐标和工具偏移不能混用。标准 GraspGen 的[官方仓库](https://github.com/NVlabs/GraspGen)列出的原生夹爪为 Panda、Robotiq-2f-140 和吸盘，并指向 GraspGen-X 处理其他夹爪。实施时应明确实际模型名称、夹爪条件和冻结版本，不把“替换生成器”的收益归给地图。

## 怎样证明这次有用

建议至少比较三组，使用同一观测、候选来源、允许修正范围、IK／路径预算和在线总时限：

| 组别 | 设置 | 回答的问题 |
| --- | --- | --- |
| A | 原候选与原规划，不修改 G | 原链路能完成什么 |
| B | 不用地图，在相同约束和范围内做局部位姿搜索 | 增加抓取自由度本身能恢复多少 |
| C | 地图引导的同类局部搜索 | 地图是否额外增加恢复，或以更少时间／调用达到相同结果 |

开发阶段先处理上述具体失败，再冻结方法和预算，使用未参与调参的案例及原成功控制做验证。保留原候选并不能自动保证成功不退步，需要实测检查选择变化、预算占用和执行差异。

分别报告终点 IK、终点碰撞、预抓取／抬升、整段路径、实际双指接触和保持成功；超时、空池、未执行单列。地图在线检索计入耗时，建图和加载耗时另外列出。仅提高末端可达分数不算达标。

如果 C 与 B 成功数相同且更慢，当前地图形式的工程收益不足；若 C 能恢复一类局部不可行姿态，同时保持抓取质量且没有过多退步，才值得继续投入更稠密的地图或学习加速。单次修复案例可证明工程可行，不能证明总体成功率提升。
