# 空闲显卡监测与自动启动

脚本为 `modules/pipeline/monitoring/gpu_auto_start.py`，当前配置为 `configs/monitoring/v4_continuation_gpu.json`。

每秒读取一次显卡的空闲显存与利用率，达到配置里的显存要求后立即提交启动命令。当前沿用实验门槛：三卡分别至少空闲23000、12000、10000 MiB，或者两卡各至少空闲23000 MiB。配置中的启动器继续完成CUDA分配探测、角色绑定和实验预检，随后才领取新场景。

已有控制器在运行时，监测只更新状态，避免重复启动。发现实验STOP、已有实际启动记录，或者新场景已经领取而控制器退出时，监测停止调度；启动后的故障沿用实验停止门控。

运行命令：

```bash
PYTHONPATH=. environments/simulation/bin/python -u \
  -m modules.pipeline.monitoring.gpu_auto_start \
  --config configs/monitoring/v4_continuation_gpu.json
```

后台服务为 `arx-v4-gpu-auto-start-20261125-02.service`。状态保存在 `tmp/resource_monitor/v4_continuation_20261125_02/status.json`，日志保存在同目录的 `monitor.log`。状态文件每5秒更新一次；显卡检测每秒进行。

当前续跑目标为原第89—100例，旧87例结果与第88例中断继续保留。后续任务可以提供新的配置，设置目标控制器、显存门槛和启动命令；命令用参数列表保存，支持 `{gpu_uuids}`、`{gpu_indices}` 和各角色的 `{rayst3r_uuid}` 等占位符。
