## 为什么能减少计算

原实现先预测输入视角，再预测21个新视角。两阶段的输入RGB和掩码相同，DINO特征可以提取一次。缓存保存输入内容的副本，后续输入即使原地修改，也会重新提取；不会复用另一个时刻的观测。

原实现还会运行训练损失和评估指标。新的纯推理入口直接调用同一套网络层，保留预测所需的全部输出；原生相机加载、深度量化、归一化、视角采样、置信度筛选和点云合并照常执行。

## 对照方式

使用此前五方法评测中保留的50组RGB、深度、SAM3掩码和相机参数，不重新采集，也不恢复已淘汰的方法。四种实现共用同一份常驻权重、同一张GPU，先统一预热，再交错执行。

每组每种实现重复3次，共600次计时，另有4次预热。物理抓取、规划和训练均为0次。

| 检查项 | 要求 |
| --- | --- |
| 输入与权重 | 输入登记哈希；权重哈希承接当前已核验登记，在GPU对照开始和结束时重新核对完整文件 |
| 输出 | 点数相同，逐点坐标最大差不超过1微米 |
| 实际调用次数 | 原实现DINO两次；复用版本一次；纯推理版本损失和指标零次 |
| 计时 | 同GPU、相同预热，CUDA同步后计时，四种顺序轮换 |
| 完整性 | 每组每种实现的三次计时、对齐记录和输出文件齐全；结束后重新读取点云独立核查 |
| 故障 | 停止并保存现场，不自动重试、不替换输入 |

GPU对照先等待 tmp/mobile_dual_arm/v4_map100_20261125_02/ 终止、所有自有组件退出且最终核验发布完成，再检查GPU空闲和CUDA分配。不会停止、重启或更改该100例任务。对照完成后生成单独的 RaySt3R计算优化结果.md，不会自动改当前主线配置。
