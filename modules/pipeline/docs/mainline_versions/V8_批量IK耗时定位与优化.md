# V8批量IK耗时定位与优化

本轮先确定批量抓取IK的时间花在哪里，再选择一项修改，比较完整规划请求的耗时。

## 已有结果

配置准备优化的完整对照已完成，两组各69/69规划通过，414个终点及414对配置核验一致。68个同次常驻运行配对的累计请求耗时减少10.26%。

优化组每请求平均的完整场景抓取IK为5.84秒，机器人与场景绑定为1.89秒，预抓取和抬升IK合计0.069秒，PRM路径为0.167秒。因此本轮先定位抓取IK，少量预抓取终点并行路径排在后面。

482次完整场景IK调用平均0.827秒，479次纯运动学回退平均0.026秒。当前CUDA事件覆盖了整段调用，包含CPU派发间隙，需要进一步区分设备真正执行内核的时间。

## 实施顺序

| 步骤 | 具体做法 | 检验内容 |
| --- | --- | --- |
| 定位 | 原五份观测，两组共10次规划。一组正常运行，一组只在第一批完整场景IK和纯运动学回退上采样CPU、CUDA内核、LM初值求解、LBFGS、指标计算与CUDA Graph捕获 | 原抓点、选臂、关节解、候选判断与完整记录一致；定位组的耗时单独使用 |
| 针对性修改 | 根据定位结果选择一个主要开销，独立实现可选优化 | 候选、32个初值、优化数值设置、精度、碰撞和路径规则保持 |
| 五场景对照 | 原五份观测按ABBA／BAAB次序共20次，不开启性能分析器 | 独立FK与记录检查通过；累计至少省5%、中位数下降、P90增幅不超过5% |
| 完整对照 | 先导三项门槛通过后，新登记69份观测、两组138次 | 原成功和原抓法保留，总请求耗时改善 |

## 固定设置

共同基线采用NMS15代表优先及全部原候选后备、B16与C版YAML写出，分支复核沿用原标量实现。使用共享内存交接、后台留档和统一预热。每臂871球、TCP43、V2指尖规则、32个初值、2毫米及0.03弧度验收保持。

启动要求可用显存至少10000 MiB并通过CUDA实算，每请求保留至少1536 MiB余量。资源、程序、配置或记录故障停止，保留原领取与停止记录。各阶段单独登记，每次请求只执行一次。

## 记录入口

定位登记：`tmp/indexed_grasp_planning/ikprofile_20261126_01/`。

定位输出包括每请求的`ik_profile.json`、第一批完整场景／回退的输入、CPU调用统计、CUDA内核汇总与Chrome时间线。算法代码位于`modules/curobo/indexed_planning/`，运行编排位于`modules/pipeline/experiments/indexed_grasp_planning/`。

本轮是保存观测的纯规划比较。有效组合确定后，另做仿真抓取回归。
