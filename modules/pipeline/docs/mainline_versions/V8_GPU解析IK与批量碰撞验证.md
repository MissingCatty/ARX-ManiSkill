# V8 GPU解析IK与cuRobo批量碰撞验证

ARX可以走“解析IK生成关节分支，再用cuRobo批量验碰撞”这条路线。当前已实现常驻GPU接口，固定一次处理256个目标、每目标最多8个普通分支，实际开爪宽度逐候选传入。

## ARX为什么适合解析求解

实际URDF中，第22、23、24关节轴平行，第25、26关节轴相交。沿关节轴移动数学原点后，可使用IK-Geo的“三平行轴＋两相交轴”分解；左右臂分别读取自己的物理链和限位。这一步只改变公式中的坐标表示。

求解依次得到肩部、腕部和肘部各两种分支，组成最多8组角度。限位、重复分支和当前目标几何会减少实际可用解数。奇异位置可能有连续解族，需要保留原数值IK回退。

参考：[IK-Geo官方实现](https://github.com/rpiRobotics/ik-geo)、[EAIK项目主页](https://ostermd.github.io/EAIK/)。新增张量实现保留IK-Geo的BSD许可证。

## 实现流程

| 步骤 | 做法 |
| --- | --- |
| 解析分支 | 使用PyTorch在GPU上并行展开256×8分支，恢复原URDF关节符号与合法的2π角度表示 |
| 精度复验 | 代数用FP64计算，输出FP32命令；再按原物理链FK检查原始目标，保持2毫米／0.03弧度标准 |
| 不同开度 | 将每候选宽度的一半分别赋给两根夹指；原生FK包含6个臂关节和2个夹指坐标，机械臂规划仍为6自由度 |
| 原生碰撞 | 用871球同时检查2048行关节状态，分别返回世界碰撞及世界＋自碰撞掩码 |
| 常驻调用 | 首次载入场景并捕获CUDA Graph，后续重复使用；尾批填充到256，输出时去掉填充行 |
| 输出保存 | 返回调用者拥有的GPU张量，下一次查询不覆盖上一批结果；另提供包含上传和下载的CPU接口 |

## 接回抓取链路的方式

原候选先保持评分和双臂交替顺序，再将抓取、预抓取和抬升终点分批交给本接口，使用其返回的关节分支接续原路径验证。无合格解析分支或处于奇异解族的目标仍保留原IK。

当前原生碰撞结果采用严格球模型；桌面拦截还要经过原V2真实网格复核，允许指尖前端10毫米范围内最多2毫米的接触。不能提前用严格球模型删掉这类可恢复候选。现有执行链的自碰撞开关保持原值，本次另测了开启自碰撞的耗时与掩码。

下一步是将该模块接入可选规划器，在同一候选顺序、相同V2规则下比较整次请求；终点通过后仍须完成原路径和抓取判定。

## 调用入口与坐标约定

代码入口：`modules/curobo/analytic_ik/session.py`。使用`environments/curobo`，通过`CUDA_VISIBLE_DEVICES`选择一张卡，接口使用该进程内的`cuda:0`。

`ExecutableAnalyticIK(arm="right"/"left")`可分别求真实左右臂。`AnalyticBatchSession`接收当前规划适配器导出的规范右臂模型，左臂场景也先经过原双臂适配器的坐标映射。输入是`body4`到`EEF`的4×4目标矩阵，不能直接传世界TCP。TCP43换算在接口外完成。

```python
import numpy as np
from modules.curobo.analytic_ik.session import AnalyticBatchSession

# robot_config、scene使用当前适配器生成的配置字典。
session = AnalyticBatchSession(robot_config, scene, include_self=False)
# poses: [N, 4, 4]，float64；widths: [N]，米；N <= 256。
answer = session.host_query(np.asarray(poses, dtype=np.float64), widths)
q = answer["q"]                       # [N, 8, 6]，float32
valid = answer["valid_collision"]     # [N, 8]，当前选定碰撞策略
fallback = answer["needs_fallback"]   # [N]，保留原IK的目标
```

GPU调用使用`device_query`，返回独立GPU张量；目标为float64，宽度为float32，均放在`cuda:0`，在创建会话的同一CUDA流调用。
