核对日期：2026年11月26日。分析记录为`tmp/indexed_grasp_planning/funnel_review_20261126_01/review.json`。

进度更新：V7已完成69份观测的NMS15＋后备与原候选规划对照，两组共用B16、各69/69通过，含后处理累计耗时1322.38→943.48秒，降低28.65%。414个终点核验通过。几何硬筛误删3条历史成功抓法，暂不启用。当前进入下一步准备：补齐完整抓法的联合批量检查，然后比较少量已知q_pre的并行路径。结果见[V7完整规划对照](V7_候选后处理规划对照结果.md)。

这份建议最值得吸收的是：先便宜地检查候选，再对少量合格关节终点并行规划。结合当前实现，下一步应重点补齐夹爪粗筛与去重、预抓取和抬升的批量联合检查，以及已知关节终点的批量路径规划。

20～60毫秒先作为待测的性能目标。当前ARX每臂871球、双臂交替、V2近桌几何与完整路径检查的实际总请求耗时，仍需由同场景对照确定。

## 二、地图不能用“邻域没有记录”硬删除

E的261个不同终点中，原IK能解出115个。将这些已解出的终点与原地图查询记录对齐，结果如下。位置查询半径均为2厘米，比较完整三维朝向。

| 查询朝向范围 | 已解出IK、但地图邻域仍无记录的终点数 |
| --- | ---: |
| 0.03弧度，约1.72° | 115 |
| 3° | 115 |
| 5° | 112 |
| 10° | 85 |

例如`M0066_S4_clutter_mug`左臂原候选0、`M0022_S2_edge_keychain`右臂原候选82，均属于原IK可解、2厘米/10°地图邻域为空的记录。

按“邻域为零就剔除”，在这批终点里会误删85个可解候选。稀疏地图没有记录表示未知。硬剔除使用有依据的运动学必要条件或实际检查结果；地图近邻和密度可以提供检索、优先级信息。

地图密度还受到关节采样分布、位置和朝向分箱的影响。它可以作为特征，但不能直接解释成该抓法对1～2厘米误差的容忍概率。需要鲁棒性时，对少量候选实际做位置和朝向扰动IK，记录测得结果。

这也延续当前地图的使用边界：为位姿可达性提供帮助，当前场景碰撞与完整路径另行确认。

## 三、夹爪粗筛、对称性和NMS怎么接

| 项目 | 建议实施方式 |
| --- | --- |
| 夹爪碰撞粗筛 | 使用当前ARX网格、每个候选的夹爪开度、TCP43和生成器原点变换，批量检查预抓取、抓取与接近扫掠区域 |
| 粗碰撞体 | OBB或粗球先找疑似碰撞；最终硬剔除继续按当前有效几何与V2规则确认，保留允许的指尖2毫米近桌接触 |
| 点云与目标接触 | 区分夹爪本体撞物、目标进入夹持腔和预期指垫接触；点云缺失按未知处理 |
| 工作空间界限 | 外边界采用当前运动链能证明的上界；内半径和接近角若未验证，先记录为特征 |
| 180°指间对称 | 单独生成带来源编号的翻转备选，检查真实双指、腕部、相机安装、限位与场景；不默认整套ARX在翻转后碰撞等价 |
| NMS | 先选代表候选优先检查，保留被暂缓候选的来源和队列；代表失败后可继续检查这些候选 |
| 回退边界 | 只恢复被NMS暂缓的候选，已被有效几何确认碰撞的候选不放回 |

6轴臂对朝向变化敏感，位置差1.5厘米、角度差15°的两个抓法，其IK结果可能完全不同。阈值应逐档比较，记录原可执行抓法被合并的情况。128或256适合作为首批代表的数量预算，后续仍保留其他候选的检查机会。

这部分放在已有V7后处理实验中比较。翻转、NMS优先级及质量排序会影响实际选中的抓法，应与只改变计算调度的V8分开记录。

## 四、预抓取、抓取和抬升保持同一条关节连接

当前已经从q_grasp出发求预抓取与抬升IK。新增工作是成批处理，并把一组抓法关联的q_pre、q_grasp、q_lift和局部连接保存为同一份记录。

初版保留当前8厘米预抓取和3厘米名义抬升。若采用笛卡尔直线进给，按连续节点跟踪IK和关节分支，再用当前碰撞与指尖规则核验实际采样轨迹。中间只查2～3个点适合提前发现失败，执行前继续检查完整连接。

关节限位裕量和归一化雅可比指标先用于排序。跨整段8厘米直接设置0.3～0.5弧度硬上限，可能删掉合法运动；应重点检查相邻节点突跳、关节限位和时间参数对应的速度、加速度。

如果后面的轨迹规划器重新解出另一组q_pre，需要重新验证它到q_grasp的连接。直接规划到已经确认的q_pre，能减少这类分支变化。

## 五、优先比较批量关节空间规划，再单独测Goalset

本地源码提供两条不同的路径：

| 接口 | 本地行为 | 对当前链路的意义 |
| --- | --- | --- |
| MotionPlanner.plan_pose，多个Goalset目标 | 重新运行IK和TrajOpt；本地分支不加入图规划种子 | 可比较多目标选择，但要保留复杂避障时的原路径回退 |
| BatchMotionPlanner.plan_cspace | 输入一批明确的关节目标；共享碰撞世界时可以使用PRM种子，按问题返回结果 | 能直接复用q_pre，减少重复IK，并按原候选顺序选择完整方案 |

因此，建议先将少量已经通过联合检查的q_pre放入BatchMotionPlanner.plan_cspace。初版比较4、8个轨迹目标的容量，而不是一开始就把64条完整轨迹都算出来。每条结果对应原候选编号，继续核对轨迹终点、局部接近、抬升和原评分顺序。

Goalset保留为另一个比较组。它寻找优化过程中得到的可行低代价结果，不能直接承诺全局最优，也不等同于GraspGen评分最高。使用它改变选择策略时，单独报告选中抓法、手臂与原组的差异。

本地plan_grasp支持在部分阶段禁用配置的接触连杆碰撞。适配时将各阶段与V2只开放指尖局部近桌接触的规则对齐，沿用当前接触检查。

## 六、固定形状之外，还要冻结每目标计算量

B已经实现固定容量补齐和有效行编号。后续IK批次容量、轨迹批次容量、Goalset大小分别配置和预热；空候选直接返回，补齐行只服务于固定形状，不参与候选竞争。

本地MotionPlannerCfg在批量大于1时，会将默认IK初值从32降为16、默认轨迹初值从4降为2。对照时显式保持原每目标初值数和优化设置，再测批量的收益。

CUDA Graph还受模型、碰撞缓冲区、张量形状和求解分支影响。记录重新捕获、模型绑定、CPU派发、数据交接与GPU求解各自耗时。原32批量的累计表现低于16，后续容量也按实际结果选择。
