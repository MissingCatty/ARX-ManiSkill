# V4：双臂规划加速

## 耗时来源

前75个已完成场景累计用时248.1分钟，其中站位前与移动后的两轮完整双臂规划共198.6分钟，占80%。SAM3、RaySt3R和GraspGenX推理合计5.4分钟。两轮规划内部，开爪检查约47.9分钟。

第76例锅铲的站位规划中，右臂约18秒找到第160名候选；程序继续让左臂逐个检查全部5048个候选，约323秒后才返回。选臂规则先比较候选的原生排名，因此左臂排名160之后的候选已不能改变最终选择。

## 两项修改

| 修改 | 原实现 | 加速实现 |
| --- | --- | --- |
| 另一臂的候选范围 | 两臂各自查找第一个可执行候选，可能扫完整池。 | 右臂找到第k名后，左臂只查前k名，包含同名次以保留关节位移比较。右臂没有找到解时，左臂仍查完整池。 |
| 开爪检查 | 每个宽度重新绑定模型、写配置、刷新碰撞世界并单独检查。 | 复用同一碰撞世界，在每个原有宽度计算原生FK，再将全部871球的关节限位、自碰撞和场景碰撞检查批量提交。 |

开爪采样间隔仍不超过0.5毫米，左臂从闭合到张开通常仍为89个采样。目标、停放臂、桌子和地面均保留。检查后恢复原生求解器的完整开爪状态，后续抓取、接近和抬升规划沿用原规则。

## 验证方式

| 验证 | 方法 |
| --- | --- |
| 原记录中的选臂一致性 | 对已保存的两臂规划结果应用排名截断，核对赢家和同名次比较。124条记录中选臂一致，按原有记录可省去67318次候选终点检查。 |
| 程序边界 | 检查排名0、同名次、更优左臂候选、右臂无解、后台故障和三类碰撞约束，17项专项与配置切换门控检查通过；43项原有回归检查通过。 |
| 全部宽度逐点一致性 | 同一机器人状态、同一碰撞世界，逐点比较旧串行检查与新批量检查的球心、半径和通过掩码。 |
| 中途碰撞故障 | 在夹指移动途中加入微小障碍，令两端均无碰撞，验证中间采样仍能正确拦截。 |
| 实际耗时与选择 | 在同一显卡、相同缓存观测和候选上交替回放原实现与加速实现，比较用时、执行臂、候选编号及世界抓姿。 |

当前100例继续使用已登记的原执行代码。加速程序在独立进程进行纯规划回放，新增物理抓取为0。验证结果写入`tmp/dual_arm_acceleration/replay_20261125_03/`。

本次只调整搜索范围和计算组织，候选原始位姿、评分、选臂优先级、碰撞球、关节限位、接触规则与成功标准保持。

## 同卡回放结果

使用同一张RTX 4090、同一份缓存观测与原生候选，原实现和加速实现交替运行。比较的是一次完整选臂规划。

| 物体 | 原实现 | 加速实现 | 加速倍数 | 执行臂与世界抓姿 |
| --- | ---: | ---: | ---: | --- |
| 苹果 | 29.9秒 | 16.3秒 | 1.84倍 | 一致 |
| 桃子 | 30.4秒 | 17.6秒 | 1.72倍 | 一致 |
| 锅铲 | 394.5秒 | 56.5秒 | 6.99倍 | 一致 |

左臂89个开爪宽度下，球心和半径与旧实现逐点完全一致，通过掩码一致；检查从15.71秒降到1.03秒。额外的中途碰撞测试在第38个采样被两种检查同时拦截，两端均无碰撞。新增实际抓取0次。

## 启用条件

切换程序为`modules/pipeline/experiments/dual_arm_grasp/activate_acceleration.py`。它要求原100例完整结束、独立验收通过、控制器和模型进程退出，再更新注册表供新登记使用。配置更新先留副本，验证失败时回滚四个配置文件。

本轮原批次在第89例接近重规划时发生CUDA非法内存访问，已结束88例、1例中断、11例未开始。原STOP与结果保留，加速实现尚未替换活动注册表。
