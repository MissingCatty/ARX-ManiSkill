# V8 场景碰撞模型更新耗时定位

第一项场景碰撞模型更新平均1.534秒，主要开销集中在完整重装碰撞场景。68个完整配对场景的优化组共1545次绑定，按原计时与操作回执逐条对应，所有分项加总一致。

## 实际耗时分布

| 调用中的操作 | 调用次数 | 单次平均 | 平均每场景贡献 |
| --- | ---: | ---: | ---: |
| 触发完整重装 | 143 | 667.69毫秒 | 1.4041秒 |
| 更新位置，部分调用同时切换障碍启用状态 | 189 | 33.10毫秒 | 0.0920秒 |
| 仅切换障碍启用状态 | 68 | 5.26毫秒 | 0.0053秒 |
| 场景未变化，复用几何 | 1145 | 1.95毫秒 | 0.0329秒 |

每次上述计时包含规划器和独立碰撞检查器两套场景更新，以及原有搜索种子与图缓存重置。143次触发完整重装的调用包含286次场景装载，其阶段计时贡献占91.52%。

## 为什么会触发完整重装

1. 每次规划请求开始，应用层复用记录会被清空。即使GPU网格缓存仍保留，首次绑定仍会重新登记整套场景。原对照的两组共用求解器，前一请求可能已修改场景，后续优化应以状态版本和内容核对管理复用。

2. 左右臂共用六轴求解器。切换活动臂时，停放臂的障碍网格随之切换，当前实现发现新几何便整场重装；规划器和独立检查器分别执行一次。

3. 三个杂乱场景已有8个网格：目标、6个干扰物、停放臂。左右臂使用不同的停放臂网格，复用合集会达到9个，超过原8网格容量，因此清空合集并重装。这三例实际分别出现6、4、5次重装类调用，其他63例为2次、2例为1次。以真实保存场景执行纯CPU策略回放，三个场景的右→左→右均重装；苹果场景第三次只更新位置，继续复用几何。

## 完整重装中的具体重活

停放臂在双臂适配器里被合成为一份世界坐标网格。苹果例的文件约6.04MiB，原始387546个顶点、129182个三角形；读取时默认处理并合并重复顶点，得到64026个顶点。

使用与底层相同的trimesh加载参数进行5次CPU复测，单次中位数为156.4毫秒。函数剖析的主要调用包括顶点合并、去重和排序；目标苹果网格的CPU读取明显更轻。新网格首次进入某个检查器时，底层还会上传顶点/三角形并创建Warp BVH碰撞查询结构。已有网格的Warp缓存可复用；现有完整测试未给GPU上传和BVH构建单独计时。

## 直接对应的优化方向

优先缓存已处理的停放臂几何，并复用不可变网格资源；场景位置和启用状态通过小量更新同步。切换手臂时避免因为增加一个停放臂网格就重装全部障碍物，按每臂原容量管理场景。每次请求的内容核对与失效管理保留。

本次完成了历史回执统计、CPU加载剖析及缓存策略回放；新增规划请求、GPU调用和物理抓取均为0。
