# V8抓取分支批量复核先导

## 本轮在做什么

在已验证的NMS15＋B16组合上，把同一个抓取位姿返回的多组关节解一起复核。原来逐组运行独立FK、关节限位和场景碰撞检查；现在批量检查，再按原顺序取第一个通过的关节解。

这是完整抓法批量检查的第一个子步骤。预抓取和抬升仍使用原IK，完整接近和路径检查继续执行；本轮会先把这些环节各自用了多久量清楚，再确定下一项优化。

## 对照设置

| 项目 | 设置 |
| --- | --- |
| 保存输入 | 已完成V7对照中的5个场景：苹果、桌边土豆、杂乱芒果、遮挡香蕉、遮挡甜椒 |
| 两组共同设置 | 15毫米／15度NMS代表优先，剩余原候选全部后备；原生批量IK容量16 |
| 控制组 | 原版逐关节分支复核 |
| 批量组 | 独立FK批量计算，原版碰撞验证器成批复核，仍取原顺序第一个有效分支 |
| 重复与顺序 | 每场景每组两次，交替使用ABBA、BAAB顺序，共20次纯规划请求 |
| 模型与设备 | 同一常驻模型池、同一GPU，每次请求重置相同求解器种子 |
| 每目标求解预算 | 原32个初值、2毫米位置精度、0.03弧度朝向精度 |
| 机器人与碰撞 | 原871球、TCP43、V2指尖规则、关节限位和场景保持 |
| 资源门控 | 启动空闲显存至少10000 MiB且CUDA实际计算通过；每请求保留1536 MiB |
| 故障处理 | 资源、程序、配置或记录故障停止后续调度，保留原登记，不自动重试 |

## 怎样判断是否可用

先检查控制组成功是否保留、选中的原候选和机械臂是否一致、三个关节终点是否一致、每个候选的通过／拒绝分类是否一致。再用完整机器人URDF独立复算预抓取、抓取和抬升终点，核对关节限位和原精度。

耗时按完整规划请求比较，同时记录每次世界绑定、批量抓取IK、独立FK、局部碰撞、预抓取IK、抬升IK、PRM路径及轨迹优化。嵌套计时同时保留包含子步骤的时间和扣除子步骤的时间，避免相加时重复统计。

先导通过正确性核验且累计耗时至少减少2%，才考虑完整69场景比较。该先导登记不会自动启动完整批次或切换默认链路。
