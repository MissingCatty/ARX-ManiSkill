# V7：原候选与NMS优先候选的规划对照

2026年11月26日，用户要求继续。在69份候选的离线验证完成后，开始实际cuRobo纯规划对照。

## 目标与分组

确认15毫米/15° NMS能否减少规划搜索耗时，同时保留原候选能规划成功的场景。本轮不做几何硬筛选。

先导已完成：两组各5/5规划通过，30个终点独立核验通过，原抓点和选臂相同。先导总耗时暂未改善；完整69场景、138次规划及414终点独立核验已完成，两组均69/69规划通过。含后处理累计耗时降低28.65%。

| 分组 | 候选搜索顺序 | IK与双臂调度 |
| --- | --- | --- |
| 原候选 | GraspGenX原评分顺序 | 批量16 IK，首轮每臂16个，之后64个轮换 |
| NMS15＋后备 | 先按原评分检查NMS代表，再按原评分检查其余原候选 | 同一批量16 IK、同一16/64调度 |

两组使用已验证的V8批量16后端，单独比较NMS顺序的影响。当前默认链路仍为V3交替搜索。

## 输入和不变条件

复用最终V6同一69份冻结观测，共166008个原候选。保持原SAM3、RGB-D、重建结果、最后站位、机器人和场景状态。每组在自己的候选快照上搜索，所有候选位姿、评分、开度和逐候选元数据完全一致。

两组使用同一卡、同一常驻模型池与相同预热流程，每场景重置相同随机种子。871球、TCP43、关节限位、位置2毫米/朝向0.03弧度、V2指尖2毫米余量、局部接近及完整路径检查保持。

## 搜索名次与原编号

NMS只改变优先级。每个队列保存“搜索名次→原候选编号”的完整对应表，两个阶段合计必须覆盖每个原候选恰好一次。

规划内部按搜索名次选择两臂方案，同名次继续比较关节移动量；对外结果另外保存原候选编号、搜索名次和是否来自后备。代表没有可行路径时，后备仍参加同样的IK、碰撞及路径检查。

原候选不被复制修改为另一种抓法。两只手从同一个共享内存快照读取，并使用已有的一次解码与后台存档契约。

## 记录哪些耗时

| 指标 | 含义 |
| --- | --- |
| 后处理 | 本次真实坐标核验、原生NMS、来源关系与队列构造 |
| 完整规划请求 | 当前开爪检查、双臂搜索、IK、碰撞、路径及请求内记录 |
| 后处理＋规划 | 前两项之和，是本次主要比较项 |
| 交接全过程 | 从后处理开始，到共享内存交出、规划返回与后台存档完成 |
| 候选检查数量 | 两臂实际检查的候选数，另外记录批量IK的实际调用 |

输入文件读取、模型加载与预热单列。规划通过和实际抓取成功分开；本轮新增感知、仿真实例和物理抓取均为0。

## 停止与资源规则

沿用启动至少10000 MiB、每次请求前至少1536 MiB余量，并在分派前做独立CUDA分配和运算检查。查询暂时不可用继续等候；CUDA检查失败的卡冷却后再候选，其他卡可以继续选。

资源、配置、存档故障停止该登记，保留所有回执，不自动重试已领取请求。普通规划失败记录后继续。先导未保留控制组成功时，保留先导数据并进入分析，不自动扩到69例。
