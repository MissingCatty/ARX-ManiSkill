# V4：高可达空间优先的站位与抓取

底盘和升降先把观测到的目标送入手臂更容易操作的区域，再在满足条件的站位之间比较移动距离。

| 顺序 | 实施方法 | 通过后做什么 |
| --- | --- | --- |
| 1. 测量目标 | 头部SAM3掩码与实测深度反投影，取可见目标点集的中位位置。 | 查询共同高可达区域。 |
| 2. 共同区域优先 | 将目标对应到两臂均为高密度的体素，反算底盘位置、朝向和升降高度，检查视野、整机终点和完整移动路径。 | 执行移动，连续确认半秒静止。 |
| 3. 到位后重新感知 | 重新拍摄并运行SAM3，核验目标仍在该高区，然后运行RaySt3R、GraspGenX与cuRobo。 | 通过后进入抓取执行。 |
| 4. 单臂区域兜底 | 共同区域受限或其抓取规划失败时，比较单臂高区站位；仍先移动再重新感知，后续规划只允许对应手臂。 | 找到可执行规划后抓取。 |
| 5. 明确失败 | 共同区与单臂区的限定搜索均未通过，记录“规划不出来”，保留具体阶段。 | 本场景结束，普通失败继续下一场景。 |

高区沿用此前已登记的推荐操作空间：使用2厘米体素，要求每臂至少29组关节采样、26个朝向桶和4个向下朝向桶。共同区内两臂同时达标，单臂区内对应手臂达标；位置前向距离至少20厘米。左右臂的平移关系已通过原始URDF和关节限位检查，实际抓姿继续通过原生IK、碰撞和轨迹检查。

每个区域最多检查1024个站位终点、32条完整移动路径；共同、右、左区域各保留一次到位后完整抓取规划的机会。未找到解时保留搜索范围、预算和碰撞原因。单臂区域之间按移动代价排序。

执行前复查图像、深度、掩码、候选和规划文件的散列，核对实时关节、底盘和升降状态。每一段底盘/升降移动分别保存命令、执行轨迹、静止回读、接触和双视角视频。资源、配置、记录损坏或未确认静止时停止后续调度。

新批次使用同一组冻结的100场景，不调整物体位置，每例一次。871球、TCP43、头部D405向下45度、1毫米物理接触偏移、V2指尖最多2毫米桌面余量及原成功标准保持。配置为`configs/experiments/sam3_graspgenx_v4_high100.json`，执行入口为`modules.pipeline.experiments.mobile_dual_arm.run`。

正式登记前先使用独立的`--development-only`登记，预算为0次抓取，只验证开发物体的站位移动、新观测和原生抓取规划交接。该验证通过、组件全部退出后，再建立正式100槽登记。
