# V8网格碰撞线程排列优化方案

## 为什么做这项修改

原五场景的10次网格查询定位已经完成，30个终点独立核验通过。四个场景的最近表面搜索比三方向射线更耗时，苹果场景两项接近。每次完整IK的首批输入包含2048组状态、每组871个球，实际网格容量为8。

原线程顺序在多个障碍物之间交替。一组32个线程只处理4个球，还会穿插空的障碍物槽位。本轮尝试让相邻线程连续处理同一个障碍物上的32个球，使其访问相同网格。

相邻线程的数据访问和分支一致性会影响GPU效率，参考[NVIDIA CUDA编程优化指南](https://docs.nvidia.com/cuda/cuda-c-best-practices-guide/)。本轮通过完整规划计时验证该排列是否有收益。

## 修改内容

| 项目 | 实施方式 | 进度 |
| --- | --- | --- |
| 实际工作量定位 | 从原完整IK捕获球查询、GPU网格、变换和参数，拆分最近点与三射线计时 | 10次完成，独立核验通过 |
| 线程顺序 | 仅替换原碰撞内核的两个索引表达式，同一障碍物的球查询连续排列 | 已实现，CPU与GPU编译通过 |
| 数学一致性 | 自动检查语法树只改变两处索引，证明每个球与障碍物组合恰好保留一次 | 离线检查通过 |
| 完整数值核验 | 用五批实际IK输入逐项比较完整碰撞代价和梯度，允许原子累加的浮点舍入误差 | 五批8919040个球通过，代价与梯度零差 |
| 五场景先导 | 原排列与新排列按ABBA／BAAB各10次，比较完整RPC请求时间 | 20/20完成，60终点核验通过，累计省18.84% |
| 完整69场景 | 先导独立核验通过，累计至少省5%、中位数下降、P90增幅不超过5%，才运行138次 | 138/138完成，414终点通过，累计省23.63% |

最近点、三方向射线、距离公式、碰撞梯度、激活距离和障碍物几何全部沿用原代码。两组完整IK各自预热和保存CUDA Graph，避免切换时沿用另一组的图。

## 比较设置

两组都使用NMS15与全部原候选后备、B16、C版YAML写出及原标量分支复核。每目标32初值、求解参数、原候选顺序、871球、TCP43、V2指尖接触规则、最终2毫米／0.03弧度门槛保持。

主计时为完整RPC请求，包含规划、记录和交接。固定查询微计时单列。每例比较原候选编号、选臂、关节终点及候选判断，并独立做FK和关节限位核验。

启动空闲显存10000MiB并通过CUDA实算后调度，每次请求前保留1536MiB余量。资源、配置、记录或程序故障停止，不自动重试已领取请求。旧登记和停止记录保留。

先导配置为`configs/experiments/indexed_grasp_kernel_layout.json`，完整配置为`indexed_grasp_kernel_layout_full.json`。本轮不切换默认链路，不新增感知、仿真或机器人动作。
