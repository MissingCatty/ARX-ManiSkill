# V8：可达性索引与批量IK加速

V8承接V4的底盘、升降和双臂抓取，与V7候选后处理并列。目标是在保持原抓取位姿和评分顺序的条件下，把可达性地图用成关节解查询库，减少重复IK搜索，缩短候选检查和规划总耗时。

当前进度：问题定位与方案登记完成，适配器待实现。V8规划回放0次、物理抓取0次。

## 为什么做

当前GraspGenX每份观测通常产生数千个抓法。规划器按原评分顺序尝试，先检查抓取终点的IK和碰撞，再检查预抓取、抬升和运动路径，找到可执行方案后停止该臂搜索。首个手臂已有方案时，另一臂只搜索可能改善选择的排名前缀。

在2026年11月25日23:54的31个配对场景快照中，GraspGenX组两臂合计产生5444次抓取终点检查：4635次当次IK未找到运动学解，750次取得运动学解后被碰撞检查拒绝，59次通过抓取终点检查。该计数来自61条含候选事件的单臂记录，用于确定本版的优化重点。

已有约1056万组前方关节见证，保存了关节角、位置和完整朝向。现有代码具有位置查询、朝向索引和经过FK核验后复用关节解的接口。V8把这些能力接入当前候选搜索。

## 数据库思路如何落地

| 思路 | 实施方法 | 要解决的开销 |
| --- | --- | --- |
| 复合索引 | 以手臂、body4系位置和完整朝向查询，绑定模型、关节限位、TCP、安装变换及地图版本 | 避免每个候选遍历整张地图 |
| 批量查询 | 一批候选一起取回邻近记录，索引和关节数组常驻内存 | 减少重复函数调用与数据搬运 |
| 已有解复用 | 对查询所得关节角独立复算FK、核对限位；达到原2毫米和0.03弧度门槛后，直接检查当前场景碰撞 | 减少重复逆解 |
| 邻近解辅助IK | 保留不同关节分支，把邻近记录作为IK初值，求解到原抓姿 | 降低从较差初值反复搜索的成本 |
| 分批计算 | 先比较16、32个候选一批，按原排名检查；找到完整可执行方案后停止后续批次 | 控制一次处理过多候选的额外工作 |
| 成功解缓存 | 保存已验证的运动学解；场景碰撞结果按机器人和障碍物状态另行管理 | 复用相似位姿的有效求解结果 |

V8链路为：GraspGenX原候选池 → 批量查询关节解 → 独立FK与限位核验／邻近解辅助IK → 当前场景终点碰撞检查 → 按原排名做路径规划 → 选臂执行。

地图没有覆盖的位姿保持未知，继续原IK求解。邻近样本只作为初值，最终目标仍是原抓取位姿。原图5毫米是位置统计格，完整六维位姿的覆盖由实际保存的关节见证决定。

## 如何判断有效

主要指标为查询、IK、碰撞和路径合计耗时的中位数与P90，以及完整规划通过率。分项记录索引命中率、直接复用数、IK调用数和初值数、终点碰撞检查数、路径规划调用数。

同时对齐原候选编号与最终手臂，列出选中抓法变化、原成功候选保留情况和失败阶段。原评分越靠前的候选仍先取得决定权；批处理时后完成的高排名结果需要先被核对，才选择后续候选。单个缓存解碰撞后，保留其他关节分支和原求解回退。

执行环节分别记录仿真时间、电脑耗时、渲染录像和重规划耗时；规划加速效果以相同资源下的规划回放为主要依据。
