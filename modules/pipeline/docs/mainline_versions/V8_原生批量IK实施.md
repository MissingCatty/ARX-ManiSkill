# V8原生批量IK实施

第一阶段把原来逐个检查的抓取终点改为成批求解，比较每批16、32个目标。左右臂仍按首轮16个、后续64个交替搜索，按原候选排名选择方案。

完整69份观测、207次规划已于2026年11月26日完成，三组各69/69通过，原抓姿及选臂全部保留；621个终点独立复算通过。批量16合计耗时降低32.84%，详细结果见《V8_原生批量IK完整对照结果.md》。当前继续C组上下文复用。

## 接入方式

| 环节 | 当前实现 |
| --- | --- |
| 对照组 | 现行交替搜索，逐个运行原IK及碰撞、路径检查 |
| 批量组 | 每个抓取目标占独立一行，分别返回关节解与结果 |
| 完整场景IK | 使用与原规划器相同的当前碰撞世界，保留871球与停放臂 |
| 近桌回退 | 完整场景IK未通过的目标再做纯运动学求解，随后执行原独立FK、关节限位及V2局部指尖检查 |
| 抓取目标 | 原世界位姿、分数、顺序与来源编号保持 |
| 后续动作 | 预抓取、抬升终点、完整路径与局部接近仍使用原实现 |
| 批次补齐 | 目标、关节状态及各状态分量统一补到固定容量；补齐行不参与候选选择 |
| 求解预算 | 每目标沿用原32个初值，完整场景返回4条、纯运动学返回8条关节解 |

新增可选模块为`curobo_indexed_planning`。接入点`native_grasp_ik`在默认实现中仍调用原单目标IK；批量实现通过该接口供应终点解，后续接触规则与动作检查共用原代码。

## 为什么要按目标分别保留初始解

直接调用整批接口时发现：同一个已知可达姿态，单独求解有解；与极远、不可达目标混在同一批时，可达姿态也可能被判为未解出。

单独检查初始解时，这个姿态仍有合格结果。原批量接口在其他目标未通过时继续优化整批，已有合格解也被重新优化，最后超出本项目的2毫米验收门槛。

当前封装按原单目标流程处理每一行：

1. 成批生成原32个LM初值，检查每个目标的结果。
2. 该目标已有合格解时，保留这些解。
3. 仅把未通过的目标连同其原32个初值送入后续优化。
4. 将结果放回原目标行，再执行原碰撞、接触和路径检查。

这样，其他失败目标不会冲掉这一行已经得到的合格解。原抓姿、初值数量和2毫米／0.03弧度标准保持。

| 接口验证 | 每批16个 | 每批32个 |
| --- | ---: | ---: |
| 原接口：可达目标与极远目标混合，可达行返回合格解 | 0条 | 0条 |
| 修正封装：同类混合输入，可达行返回合格解 | 6条 | 6条 |
| 修正后返回解的独立FK | 通过 | 通过 |

以上是求解接口验证。初始解采样随调用推进，表中合格解数量用于确认该行仍有可用解。规划耗时由后续同卡完整请求对照测量。

原接口定位记录在`tmp/indexed_grasp_planning/ik_rows_20261126_03/`，修正封装验证在`ik_rows_20261126_04/`。均只计算IK，仿真实例、轨迹执行与物理抓取为0。

## 已完成检查

20项新离线检查和11项原交替搜索回归通过，后者包含72组排序组合。覆盖原候选不变、重复位姿的来源编号、回退行映射、补齐行不参与选择、已通过初值不被其他行覆盖、错误传播、独立FK和邻物碰撞规则。

GPU接口检查同时包含已知有解、明显无解、两种混合顺序及两个不同的可达目标；返回的合格解经过当前物理URDF的独立FK复算。

## 规划对照

先导使用苹果、开阔香蕉、盒装食品、稀疏香蕉和杂乱橙子五份保存观测，三组共15次完整规划。通过后，以最终V6同一套69份观测登记207次规划请求。5例共同站位失败保留在74例总体中。

每组共用同一显卡、常驻模型、共享内存交接和原候选。每目标初值预算保持，组别先后顺序轮换。先预热有解和无解两类求解路径，初始化耗时单列。记录整次请求的中位数、P90、规划通过、选中抓法和手臂变化。

### 五场景先导结果

先导登记`native_batch_pilot_20261126_05`已完成15次规划。三组均为5/5通过，选中手臂、原候选编号和原世界抓姿全部一致；预抓取、抓取和抬升共45个终点的独立FK与关节限位检查通过。

| 方法 | 规划通过 | 请求中位耗时 | P90耗时 | 五次累计耗时 |
| --- | ---: | ---: | ---: | ---: |
| 现行逐个检查 | 5/5 | 8.84秒 | 65.20秒 | 133.84秒 |
| 批量16个 | 5/5 | 9.92秒 | 46.58秒 | 108.95秒 |
| 批量32个 | 5/5 | 9.25秒 | 47.93秒 | 108.64秒 |

先导中，短搜索案例增加了预计算开销，杂乱橙子的长搜索缩短。批量32组累计用时下降约19%，其中位数仍高于控制组。随后已完成全部69份观测，整体以批量16更优。

完整回放为`native_batch_69_20261126_01`，三组共207次规划。`native_batch_followup_20261126_02`已完成独立复算与公网发布。

模型、机器人、场景物理、每臂871球、TCP43和V2指尖规则沿用当前配置。当前默认规划器继续使用已验证的交替搜索，物理抓取预算0。
