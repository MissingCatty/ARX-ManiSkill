# V8 内存状态更新完整抓取测试方案

2026年11月28日，用户要求优化完成后进行完整测试。本轮承接纯规划平均7.02秒降至4.40秒的内存更新实现，检查它在实际抓取各阶段是否正确。

| 项目 | 做法 |
| --- | --- |
| 场景 | 沿用74个配对场景，原方法和内存更新各74个登记槽；5个原站位前提未满足场景每组保留为未执行，其余69个场景每组实际尝试一次 |
| 输入 | 同一冻结头部RGB-D、SAM3掩码及15毫米／15度NMS后的候选；本轮比较规划与执行，感知不重新推理 |
| 复位 | 每槽重新创建场景、恢复冻结机器人与物体状态，记录静止轨迹并核对恢复误差 |
| 执行 | 先按候选实际宽度开爪，到预抓取位后用实测状态重规划接近，到位闭合；闭合后用实测夹爪状态重规划抬升，保持3秒 |
| 冻结设置 | 每臂871球、TCP43、V2指尖前端10毫米最多2毫米桌面余量、原32初值及2毫米／0.03弧度验收、原物理与成功标准 |
| 记录 | 初始规划、接近重规划、抬升重规划分别计时；双视角录像、关节／物体轨迹、接触点、命令与请求账齐全 |
| 独立评估 | 目标最低保持抬升至少1厘米并持续3秒，双指接触、完整到位、无禁止接触；命令路径、原始候选与实际启用方法另核查 |
| 故障处理 | 普通抓取失败继续；资源、配置、记录损坏或无法确认机器人空闲时停批，保留现场，不自动重试 |
| 输出 | 两组规划和抓取成功率、失败分布、各阶段耗时及录像；原5个未执行与实际规划失败分开 |

本轮使用GPU2，允许共享。启动总余量14GiB级门槛、规划器10GiB级门槛及逐请求1536MiB保持；模型预热常驻后顺序执行。原40次纯规划及全部旧结果继续保留。

入口为`modules.pipeline.experiments.state_update_execution`，最新记录位于`tmp/state_updates/execution74_20261128_03`，通过`execution_active.json`定位。首登记的6个完整槽继承保留，其余槽继续执行，总预算仍148；当前抓取默认入口不因这轮测试自动切换。
