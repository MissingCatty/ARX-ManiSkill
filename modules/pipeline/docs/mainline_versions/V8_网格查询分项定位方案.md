# V8网格查询分项定位方案

上一轮五批GPU采样中，离散碰撞查询占内核时间97.75%。精确两票短路的20次先导累计只省3.19%，中位耗时上升，未展开69场景。

本轮先把网格查询进一步拆开，在规划器真实使用的同一批点上，比较最近点搜索、三方向射线投票和合并查询。

| 步骤 | 方法 | 验收内容 |
| --- | --- | --- |
| 取得实际查询 | 原五场景、两组共10次规划。正常组沿用原计算，定位组只在第一批完整场景IK中复制一次实际碰撞球查询 | 原抓点、选臂、关节解及候选判断保持 |
| 固定查询与网格 | 保留原宽相检查放行的查询、局部坐标、搜索半径，以及GPU实际网格和变换 | 文件散列、点与网格对应关系完整 |
| 分项计时 | 同一批数据分别执行最近点、原三方向投票、合并查询，同时测原碰撞派发；预热并用CUDA Graph重复计时 | 最近面、重心坐标、有效标记和内外符号逐位一致 |
| 选择一项修改 | 根据分项计时和原内核的数据排列选择主要开销；修改作为可选实现单独登记 | 原候选、32初值、优化器数值设置、871球、TCP43、V2及精度保持 |
| 规划对照 | 原五场景20次ABBA／BAAB；独立核验及原三项时延门槛全部通过后，新登记69场景两组138次 | 累计至少省5%、中位下降、P90增幅不超过5% |

分项计时使用固定查询点。各子步骤单独执行，原完整派发另列；分项时间不直接相加替代整次规划耗时。定位组的采样时间不作为优化收益。

启动仍需至少10000 MiB可用显存及CUDA实算通过，每请求保留1536 MiB余量。资源、程序、配置或记录故障停止，原登记与停止回执保留。当前只开展保存观测的规划与GPU查询，没有新增感知、仿真或机器人动作。

登记入口：`tmp/indexed_grasp_planning/queryprobe_20261126_01/`。代码位于`modules/curobo/indexed_planning/query_probe/`，原模块与默认设置保持。
