# 场景几何复用接口

实现位于`modules/curobo/scene_reuse/`。模块接收已经确认内容的场景几何，提供CPU处理结果复用、GPU不可变资源复用和场景槽位更新三个独立接口。

## 模块组成

| 文件 | 职责 | 输入与输出 |
| --- | --- | --- |
| `prepared_meshes.py` | CPU顶点及三角形缓存 | 输入原生Mesh对象，返回只读顶点和面索引；记录处理、内存命中、磁盘命中 |
| `cpu_runtime.py` | 将CPU数组接入原生GPU加载函数 | 逐实例安装适配器，GPU上传和BVH构造仍由原函数执行 |
| `gpu_runtime.py` | 共享原生Warp网格和BVH | 按内容、缩放、库版本和设备取得资源，为各消费者返回独立名称记录 |
| `slot_scenes.py` | 增量同步当前场景 | 按目标、干扰物、停放臂等逻辑角色维护槽位，返回更新事件及计时依据 |
| `runtime.py` | 构建可选规划器 | 复用已验收的内存状态更新规划器，安装CPU计时及复用接口 |

双臂选择、候选顺序、IK及轨迹规划继续由原模块负责。实验编排位于`modules/pipeline/experiments/scene_reuse/`，负责冻结输入、选择对照变量、加载预热、领取请求、记录和独立核验。

## CPU缓存

`PreparedMeshCache(root, maximum_memory_bytes).get(mesh)`返回`PreparedMesh(vertices, faces, key)`。首次使用调用原生`get_mesh_data(process=True)`，相同内容可以从内存或磁盘取得。缓存标识包括完整文件哈希、缩放、处理选项及NumPy/Trimesh版本。

磁盘条目使用`vertices.npy`、`faces.npy`和`metadata.json`，数组读取关闭pickle。发布时原子替换完整目录，读取时核对数组哈希；处理失败、内容变化和文件损坏都会进入对应的异常处理。内存使用有上限的LRU缓存。

缓存目录统一为`tmp/curobo/mesh_cache/`下的运行目录。CPU缓存先导为`scene_reuse_cpu5_20261128_01`：CPU处理188→66次，完整RPC累计省4.38%，保留可选。

## GPU资源共享

`GPUGeometryReuse(stores)`为指定的原生MeshData实例安装私有加载适配器。`begin(enabled=True)`开始当前请求的共享，`finish()`返回加载、命中及句柄记录。

共享对象为顶点、三角形和Warp网格/BVH。每套检查器的障碍位置、启用标志、槽位、尺寸和包围范围仍位于自己的存储中。资源创建继续调用原生加载函数，消费者通过各自的`wp_cache`持有强引用。请求结束清空中央索引后，仍在使用的消费者继续持有其资源。

GPU共享先导为`scene_reuse_gpu5_20261128_01`：原生GPU网格创建188→66次，完整RPC平均4.061→3.384秒，累计省16.67%，通过本轮可选实现门槛。原生碰撞结果及消费者独立更新、释放核验通过。

## 固定槽位

`SlotSceneUpdates(config_factory, pose_factory, digest)`实现与原场景更新器相同的`reset`、`update`、`report`接口。网格使用逻辑角色分配槽位，并核对完整内容哈希；几何改变时替换该槽位的句柄、尺寸和包围范围，位姿与启用状态分别更新。

每次请求边界核对原生场景存储的名称、句柄、位姿、尺寸和启用状态。上一请求结束后的状态未变化时复用；外部修改或清空时使对应记录失效。核对放在请求边界，绑定循环内只更新实际变化。

固定槽位先导为`scene_reuse_slots5_20261128_01`：整场重装96→30次，连续切臂和跨请求核验通过；完整RPC增加7.28%，保留可选。
