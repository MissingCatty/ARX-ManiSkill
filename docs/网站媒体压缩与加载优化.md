## 页面如何加载

- 图片使用 WebP，生成 480、960、1440 像素宽及原宽度版本，浏览器按实际显示大小选择；滚动到附近才加载。页面中原有的点击放大链接继续打开原图。
- 视频使用 H.264 压缩，保留原来的分辨率、帧率和时长；MP4 索引放在文件开头，支持拖动和分段请求。视频点击播放后才下载。
- 网页和脚本提供 Brotli、Gzip，服务根据浏览器支持的格式自动选择。
- 压缩文件带内容指纹，可长期缓存；图片或参数变化后会生成新地址。

视频共核验 3722 帧。六段视频的平均结构相似度均不低于 0.9943，所有单帧均不低于 0.9927。本次均通过压缩质量门槛。

## 后续使用

在 `website/` 中运行 `npm run build`，会先复制发布资源，再自动补齐压缩文件，最后整体更新页面。没有变化的文件直接复用缓存。`npm run optimize-media` 可以单独准备压缩缓存。

参数集中在 [media-policy.json](../website/media-policy.json)。当前图片质量为 86；视频采用 H.264、CRF 24，平均结构相似度门槛为 0.985，最低单帧门槛为 0.96。质量不达标时提高编码质量；仍未通过则保留原编码并前置 MP4 索引。

新增媒体的压缩需要支持 WebP 的 Pillow 及 FFmpeg。当前自动使用工程的 `environments/simulation/bin/python`；迁移时可用 `ARX_MEDIA_PYTHON` 指定环境。缓存齐全的网站构建、启动只需要 Node.js。

网站的原始副本、压缩副本和发布页面均是 `website/resources/` 内的真实文件。删除实验目录后，网站仍可独立构建和运行。移除发布源文件后，旧压缩缓存不会把它重新加入页面。
