# 网站独立发布规范

网站实际目录为工程根目录的 `website/`。发布后需要保留的内容全部属于网站自身，实验目录只作为生成新页面时的数据来源。

```text
website/
├── build.mjs                     页面构建
├── server.mjs                    独立 HTTP 服务
├── published-resources.mjs       发布资源复制、校验和登记
├── package.json / package-lock.json
├── node_modules/                 网站自己的依赖
├── 内容/                         Markdown、版本树、流程和图集配置
├── 页面/                         前端样式与交互代码
└── resources/
    ├── authoring_media/          图集等内容生成文件
    ├── media/                    已发布图片和视频的真实副本
    ├── optimized/                WebP多尺寸、压缩视频、缓存登记与构建统计
    ├── metadata/                 统计数据与文档快照
    ├── attachments/              Markdown、JSON、CSV 等下载附件
    ├── site/                     构建完成的页面与全部静态资源
    ├── state/                    待办数据库
    └── manifest.json             本次资源 SHA256 登记
```

## 每次生成网页都执行的流程

1. 从实验记录提取正文、表格和媒体清单。
2. 将所有引用的图片、视频、统计数据和附件复制到 `website/resources/`，生成 SHA256 登记。
3. 自动检查媒体压缩缓存：图片生成 WebP 多尺寸预览，视频通过质量检查后使用压缩副本；原图点击入口继续保留。参数由 `website/media-policy.json` 管理。
4. 从网站内部副本生成页面，文本同时生成 Brotli/Gzip，图片按页面尺寸加载，视频点击后加载。视频对外仍使用原来的 `/media/...` 地址。
5. 构建成功后整体替换 `resources/site/`，网站读取这个完整快照。
6. 检查页面引用的媒体是否齐全；定期运行独立副本验证。

资源必须是实际文件，不能用指向实验目录的软链接或硬链接代替复制。发布流程遇到源文件已删除时，可使用网站已有快照；新增资源缺失时构建报错。

网站需要迁移时，可以只复制 `website/`。已有依赖一起复制后直接用相同版本 Node.js 启动；也可用 Node.js 22.13 及以上版本和 `npm ci` 安装锁定依赖。服务与已生成页面不需要机器人、模型权重或仿真环境。

待办数据库保存在网站自身的 `resources/state/`。清理 `tmp/`、删除实验代码和模型时，不删除网站资源副本。删除某个已发布展示内容时，单独修改网站内容登记。

## 媒体更新

`npm run build` 会自动补齐新媒体的压缩文件，并按原文件和参数的 SHA256 复用已有缓存。也可用 `npm run optimize-media` 单独准备缓存。现有缓存齐全时，独立网站重新构建和启动只需 Node.js。

首次压缩或新增媒体时，需要支持 WebP 的 Pillow；视频压缩使用 FFmpeg，可由 imageio-ffmpeg 提供。当前机器自动使用 `environments/simulation/bin/python`。新机器可以将 `ARX_MEDIA_PYTHON` 指向安装了这些依赖的 Python；`FFMPEG_EXE` 可指定 FFmpeg。

图片默认 WebP 质量86，提供480、960、1440像素及原宽度版本。视频保留原分辨率、帧率和时长，逐帧计算压缩前后的结构相似度；平均值至少0.985、最低帧至少0.96才采用更小的重新编码文件。未达到时保留原视频编码，调整MP4索引位置以便流式播放。原始网站媒体继续保存，压缩不会改写实验记录。
