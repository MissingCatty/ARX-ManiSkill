# 安装与运行

## 当前机器

在工程根目录执行：

```bash
python3 -m arx_project inspect
environments/simulation/bin/python -m arx_project doctor --verify-dataset
python3 -m unittest discover -s tests -v
```

`inspect` 查看模块与环境；`doctor` 检查文件、权重、当前配置与冻结场景；接口测试只使用离线替身。

当前实际配置为：871 碰撞球、TCP 43 毫米、固定升降 45.2 厘米、头部 D405 向下 45°、物理接触偏移 1 毫米。场景为独立采样的 200 例，包含 40 类、80 个模型、5 种布局，每种布局 40 例。

当前场景唯一入口为`simulation/scenes/latest200/`，三维模型集中在`simulation/assets/models/`。共享资产定义为`simulation/assets/catalog.json`，场景通过资产ID引用。交付时保留这两个目录及共享索引的相对结构。

## 环境划分

| 环境 | 用途 |
| --- | --- |
| `environments/simulation/` | ManiSkill / SAPIEN、场景与执行 |
| `environments/sam3/` | SAM3 分割 |
| `environments/reconstruction/` | RaySt3R 点云重建 |
| `environments/graspgenx/` | GraspGenX |
| `environments/curobo/` | 当前 cuRobo 规划 |
| `environments/curobo_v090/` | 独立的新版本适配 |
| `environments/graspcl/` | ZeroGrasp 基线与 GraspCL 依赖 |
| `environments/spar3d/` | SPAR3D，保留待确认 |
| `environments/runtime_bundle/` | 共享 Python、CUDA、编译工具和运行依赖 |

各环境的 Python 版本和依赖分别记录在 `configs/environments/manifest.json` 与同目录的文本清单。

## 换目录或交给新用户

代码、`simulation/` 和 `weights/` 一起交付；需要保留历史记录时再带上 `tmp/`。网站可以单独交付 `website/`。

同系统迁移现有环境后先运行：

```bash
python3 tools/bind_environments.py
environments/simulation/bin/python -m arx_project doctor --verify-dataset
```

绑定工具修正可编辑安装、环境脚本和项目内解释器链接中的旧路径。当前200场景的摆放、初态和参考观测保持原字节；资产引用、登记和冻结清单在本次存储整理后重新绑定，原散列及承接记录保存在`tmp/scene_storage/normalize_20261124_01/`。

新机器按 `configs/environments/manifest.json` 的 Python 版本创建对应环境，再按依赖清单安装。清单中的 `${ARX_PROJECT_ROOT}` 指向新工程根目录，例如：

```bash
export ARX_PROJECT_ROOT="$PWD"
python3.12 -m venv environments/simulation
environments/simulation/bin/python -m pip install -r configs/environments/simulation.txt
python3 tools/bind_environments.py
```

CUDA 扩展按目标机器的 CUDA、PyTorch 和显卡架构编译；上游源码、许可证和依赖清单随工程保留。具体模型环境按注册表逐一安装，不合并为一个大环境。

## 服务入口与运行目录

服务通过当前环境启动，例如：

```bash
environments/sam3/bin/python -m arx_project serve \
  --kind sam3 \
  --root tmp/sam3_graspgenx/run_001/resident \
  --socket tmp/rpc/run_001/sam3.sock \
  --warmup-trial tmp/sam3_graspgenx/run_001/preflight/head_warmup \
  --descriptor tmp/sam3_graspgenx/run_001/gripper_descriptor.json
```

启动前应已准备对应观测、描述文件和 GPU 环境。实际实验入口会安排组件的环境与预热顺序，无需手工启动四遍。

当前完整执行入口仍为 `modules/pipeline/experiments/repaired_grasp_benchmark/run_repaired_benchmark.py`。本次整理后的抓取授权为关闭、预算为 0；需要开始新实验时建立新的授权登记，保留已有停止标记。

## 网站

```bash
cd website
npm run build
npm start
```

当前机器的开机自启仍由 `claro-arx-progress.service` 承接，端口为 8786。Windows 原有 SSH 转发继续使用该服务端口。

独立网站校验：

```bash
python3 tools/validate_website.py
```

它会创建一个网站副本，在没有实验目录的情况下重新构建、启动并检查页面、媒体、视频分段读取和待办接口；结束后删除验证副本。
