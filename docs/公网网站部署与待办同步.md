## 更新顺序

1. 本机导出最新待办，将代码、网站资源与快照推到Git。
2. 在公网主机的新暂存目录同步完整网站，保留网站自己的依赖、图片、视频与附件；核对依赖锁文件，使用本机已经验证的构建结果。
3. 在暂存目录恢复待办快照，核对所有条目、完成状态与编号序列，并以独立端口测试页面和API。
4. 停止公网网站服务，保存旧网站、旧数据库及服务配置，将验证过的暂存目录切换到正式路径，再启动服务。数据库目录由`arx-web`持有，静态资源保持Nginx可读。
5. 从公网检查首页、最新版本、升级计划、媒体和待办；保留备份位置、提交编号、文件校验和及验证结果。

`CLARO_HOST=127.0.0.1`用于保持后端仅在本机监听。待办接口同时支持HTTP同源请求，以及经本机HTTPS反向代理转发的同源请求。部署时保留现有代理入口。

## 待办迁移

本机在网站目录执行：

```bash
node tools/todo_snapshot.mjs export
```

暂存网站目录执行：

```bash
/opt/arx-maniskill/environments/node/bin/node tools/todo_snapshot.mjs restore --replace
```

恢复命令会先保存已有数据库备份，再导入快照。首次创建数据库时也会自动读取快照；普通重启继续使用现有数据库，不重复导入。若公网已有新增待办，先对比两端条目，再确定合并内容。
