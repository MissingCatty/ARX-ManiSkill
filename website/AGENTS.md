# 网站内容与表达约定

- 网站独立位于工程根目录website。每次发布将所有使用的图片、视频、附件和统计数据复制到resources内；使用真实副本，不链接实验目录。发布后须验证只保留网站目录也能启动、浏览媒体和使用待办。实验产物后续删除不得影响已发布内容。
- 构建统一通过media-optimization.mjs处理图片、视频和文本。图片生成WebP与响应式尺寸，点击原图入口保留；视频使用质量核验后的H.264、前置索引和preload=none；文本提供Brotli/Gzip。参数与缓存分别归入media-policy.json及resources/optimized。原图和压缩文件都属于网站真实副本，不得将压缩文件写回实验资产。

- 页面围绕当前主题和用户要求，讲清楚做了什么、结果怎样，以及读者需要理解的过程。
- 直接陈述工作和结果，省去主动辩解、免责措辞、无关的范围声明，以及对未要求事项的反复解释。
- 使用通俗、完整的中文。步骤之间的关系和结果的含义要讲明白，不为了显得专业或压缩字数而堆缩写、术语和短句。
- 表格使用容易理解的列名，说明数字代表什么、怎样比较。失败结果与实际数据如实展示。
- 由脚本生成的页面，同步修改生成模板，让后续发布继续沿用用户确认的内容和表达方式。
- 新增代码、配置和目录使用英文名；docs内的说明文档使用中文文件名。
- 实验主页、内部版本、运行批次分层维护，内部代号为V1至Vn。只有用户明确要求新开实验迭代时才能新增版本，并在`内容/experiments.json`登记用户要求与方案设置；文字、界面、小修和重复运行都不新增版本。重复运行记为批次，不自动扫描批次生成版本。
- 可达性改进下的V1 GraspCL、V2固定45.2 cm高度、V3升降联合规划、V5先升降后固定高度抓取是并列方案，不创建递进继承关系。CLARO归入遮挡情况处理的V1；旧阶段记录不自动升级为迭代版本。MPC已封存，保留历史入口与结果。
- V2和V3当前只展示ZeroGrasp＋cuRobo的设置、结果和失败原因。页面正文与原生管线统计由`tools/refresh-reachability-pages.py`更新；原始双管线结果保留在源资料中，不放入这两页的摘要、对比表或批次页。重写正文仍沿用现有V2和V3，不新增版本。
- 配置与核查由三个独立详情页组成：200个评测场景、夹爪配置（TCP与碰撞球）、可达范围检查（末端与桌面核查、前方地图、高度比较）。旧配置锚点指向所属详情页。

- 用户明确要求新增V5“先升降、固定高度抓取”，与现有方案并列。V3在内部版本树及详情页标为已封存，原页面、入口、历史结果和批次保留。V5目前是待验证的串行执行方案，无实际测试成绩或运行批次，不把现有V2/V3成绩转记给V5。

- 已封存实验及内部版本的详情页、所属批次页统一展示归档原因，使用区别于普通正文的提示卡；原有内容默认折叠。目录和直接章节链接应自动展开对应内容后定位。
