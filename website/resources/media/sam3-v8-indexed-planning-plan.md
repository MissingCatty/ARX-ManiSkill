# V8：可达性索引与批量IK加速

V8的目标是缩短候选检查与整次规划请求的耗时，保持原抓姿和评分顺序。以已启用的双臂交替搜索为基线，分别比较原生批量IK、几何IK、关节解索引和状态绑定复用，再组合有效部分。

当前进度：B批量16完整对照合计省时32.84%；C完整对照合计省时2.33%，保留可选；D五场景20次规划与60个终点复核通过，但累计慢6.14%，未扩到69场景。E的10,322次CPU查询与3,132次实际IK对照均完成，四组解出情况相同，10°组累计耗时增加0.20%，当前不纳入组合。原01停止记录保留；02由监测器自动在GPU3执行完毕。物理抓取0次。结果及方法分别见《V8_原生批量IK完整对照结果.md》《V8_上下文复用实施.md》《V8_几何IK实施.md》《V8_地图索引复用实施.md》。

## 分开比较的方法

| 分组 | 相对现行交替搜索的变化 | 目的 | 当前进度 |
| --- | --- | --- | --- |
| A：现行基线 | 当前逐候选IK、碰撞与路径检查 | 建立优化后的真实对照 | 69份回放完成 |
| B：原生批量IK | 每次成批处理16或32个候选，逐行返回结果 | 降低重复调用与小任务开销 | 完整对照完成，优先保留批量16 |
| C：绑定复用 | 同一请求内复用每臂模型与场景上下文 | 减少交替窗口重绑定开销 | 138次与414个终点复算通过，总省时2.33% |
| D：几何IK | 用EAIK/IK-Geo为原目标生成多分支解 | 利用ARX三个平行转轴的结构 | 20次通过但累计慢6.14%，未扩展 |
| E：索引复用 | 查询地图与成功解缓存，直接验证或辅助求解 | 测量查表是否值得 | CPU查询与3,132次IK完成，当前没有总耗时收益 |
| F：有效组合 | 组合单独验证后有收益的模块 | 比较最终总耗时和效果 | 待各分组结果 |

B和E分开，便于看清提速来自批处理还是地图；几何求解和绑定复用也分别测量。最终按结果确定组合。

## 原生批量IK

本地cuRobo已有`solve_pose`批次接口，当前纯运动学辅助求解器仍配置`max_batch_size=1`。新适配器建立16、32目标的独立常驻求解器，统一预热固定容量的CUDA图。

一个候选占一个批次行，保留原来源编号、目标、每目标种子预算与返回分支。最后一批补齐时记录有效行，仍由原排名决定完整路径检查顺序。采用逐行批次，保留每个候选的独立结果。

批量层按每个目标分别保留已经通过的LM初值，只有未通过的行继续原优化；每目标32个初值及原验收条件保持。实施及先导结果见《V8_原生批量IK实施.md》。

两层求解都沿用当前顺序：先批量运行完整场景IK；未通过的行再批量运行纯运动学回退，并逐行进行独立FK、限位、非桌面碰撞和V2局部近桌检查。批次张量固定形状、连续存储，补齐行屏蔽。

16/64是左右臂调度窗口，16/32是GPU求解批量，前者在所有组保持一致。终点通过后继续原预抓取、抬升、局部接近和完整路径检查。

## 几何IK

当前URDF中right_joint22/23/24轴平行，最大叉积范数2.45×10⁻¹⁶；right_joint25/26轴线相交。该几何核查支持优先验证IK-Geo/EAIK的三平行轴求解分解。

1. 在独立环境导入当前六轴链和EEF工具变换，核对自动识别的机器人家族。
2. 从合法关节状态做FK生成目标，检查所有返回分支与独立FK、关节限位。
3. 将角度映射到原限位内的2π等价表示，保持原目标和工具偏移。
4. 按原2毫米、0.03弧度门槛验收，再执行当前场景碰撞与路径检查。
5. 无合格分支时调用原IK，记录回退成本；最小二乘输出同样按原误差门槛验收。

EAIK 1.2.2已在独立CPU环境完成适配，27项检查通过。另用完整物理URDF复算256个随机状态及原69份规划的207个终点，全部通过；207个终点的几何求解与限位、精度筛选中位耗时1.58毫秒。完整请求耗时由D先导和配对回放测量。详见《V8_几何IK实施.md》。

## 索引与缓存

| 环节 | 实施方式 |
| --- | --- |
| 查询空间 | body4下的TCP43位置与完整旋转，绑定物理手臂、安装变换与模型版本 |
| 常驻数据 | 使用现有约1056万组关节见证，索引与数组加载一次 |
| 直接复用 | 独立FK与限位通过后检查当前场景碰撞 |
| 邻近初值 | 为原目标提供初值，记录其实际进入LM与后续求解的过程 |
| 多分支 | 保留不同关节分支，继续碰撞、前后动作和路径检查 |
| 未覆盖 | 调用原求解路径并计入完整耗时 |
| 缓存 | 保存运动学解；碰撞结果随当前机器人与障碍物状态重新检查 |

现有位置查询一次取8192个邻居，需要测CPU查询与旋转筛选成本。现有重力方向索引适合允许底盘转向的必要条件筛选；固定站位查询要加入完整旋转比较。

已完成原2毫米、0.03弧度下的直接命中率统计，10,322次查询命中0次。初值查询采用更宽的2厘米位置半径，分别比较3°、5°、10°朝向范围；命中32、142、698次。附近关节角仍用于求解原目标，最终验收精度保持。具体结果和下一步对照见《V8_地图索引复用实施.md》。

VAMP / VAMP-MR属于后续FK与碰撞检查向量化的参考，目前尚未实施，不属于B、C、D已测模块。

## 比较与记录

同一套69份保存观测、候选和测得机器人状态用于全部分组。共同站位失败5例保留在74例范围中，SAM失败和原中断单列。

先用长串失败、较晚找到抓姿、短搜索和单臂占优的输入做接口回放，再覆盖全部69份。相同显卡、相同初值策略、统一预热，交替组别顺序；短时计时多次重复。首轮地图和缓存冻结，在线增加成功记录的热缓存另组比较。

主要指标为整次规划请求的中位数、P90和规划通过率。分项记录解码、查询、模型/场景绑定、开爪、IK、终点碰撞、完整路径及交接。CPU派发、CUDA同步墙钟和GPU事件计时分别记录，加载预热单列。

同时记录原成功输入的保留、选中来源编号与手臂变化。新的关节分支可能使更早的原候选变得可执行，需要说明变化原因；原成功输入发生回退时单独定位。最终方案依据总耗时下降、规划效果保留及后续实际验证决定。

用户已于2026年11月26日授权开始，并要求完成后继续。B原生批量阶段的15次预检与207次完整回放已结束；C先做20次重复对照，通过正确性与收益门槛后登记138次完整比较。物理抓取预算0。默认链路继续使用已验证的交替搜索，各加速器作为可选模块运行。
