# V8几何IK实施

D组使用EAIK为原抓点生成多个关节角解，再沿用当前碰撞、接近和完整路径检查，比较整次规划是否更快。实现放在现有V8可选模块内部，采用独立CPU环境。

## 五场景先导结果

20次规划全部完成，两组各10/10通过；抓姿、选臂和候选检查数一致。60个终点独立FK及原关节限位核验通过。

| 方法 | 中位耗时 | P90耗时 | 10次合计 |
| --- | ---: | ---: | ---: |
| 原逐个IK | 7.75秒 | 67.61秒 | 204.83秒 |
| D：几何IK优先、原IK回退 | 7.34秒 | 74.19秒 | 217.42秒 |

累计耗时增加6.14%，未达到省时2%的扩展门槛，未开展69场景对照。D当前实现保留为可选，后续优先比较E索引复用，再与已有效的B批量16组合。

两组各检查1434个候选。D组中，1200个没有通过限位与精度筛选的几何分支，198个有几何分支但未通过后续终点检查；36个几何终点通过，其中22个在接近、抬升或路径阶段失败，再完整尝试原方法。只有14个候选完成了几何分支的完整路径检查。

因此，本轮绝大多数候选仍执行原IK，新增的几何求解、验证及回退流程提高了总耗时。207个已成功规划终点的快速求解证明了数学接口可用；在完整候选池上，主要开销来自大量未通过的候选。

## 参考与接入

[EAIK项目主页](https://ostermd.github.io/EAIK/)和[官方源码](https://github.com/OstermD/EAIK)提供自动识别平行轴、相交轴结构的几何求解接口。本项目使用1.2.2版，ARX左右臂均被识别为三个内部平行轴的六转轴结构。

| 环节 | 实施方法 |
| --- | --- |
| 机器人来源 | 读取共享资产中的实际ARX URDF，分别核对左右臂和真实关节限位 |
| 求解目标 | 原候选从TCP43换算到EEF，再转换到当前规划基座坐标系；世界抓姿和评分不变 |
| 轴向约定 | 三条平行轴先统一方向供几何分解，返回角度按对应符号还原到原URDF方向 |
| 超过180°的限位 | 枚举合法的2π等价角度，保留原限位内的分支 |
| 几何筛选 | 重新计算物理链FK，按原2毫米、0.03弧度标准验收；最小二乘输出也经过此检查 |
| CPU与GPU交接 | 独立CPU进程常驻，通过管道一次传16个原目标，不重新读取候选文件 |
| 当前场景检查 | 返回角度转为实际使用的float32后，再查原限位、独立FK、871球、停放臂与V2近桌规则 |
| 没有合格几何分支 | 继续原完整场景IK及纯运动学回退 |
| 几何解后续接近或抬升失败 | 在同一个原候选上完整尝试原方法，再检查下一排名 |
| 方案选择 | 仍按原候选顺序及双臂16/64交替调度；记录选中候选与手臂变化 |

四处原限位及几何检查均使用物理URDF角度。转换轴方向和2π表示只改变数学表示，不改变机器人、抓姿或关节活动范围。
