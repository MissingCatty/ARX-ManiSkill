# ARX 抓取项目进度与成果网站

同一局域网访问 [claro-arx.local:8786](http://claro-arx.local:8786/)。也可使用主机的内网 IP 和端口 8786。名称通过 mDNS 在同一组播网段公布。终端需支持 `.local` 解析。跨 VLAN 时可用内网 IP 或由网络管理员配置内网 DNS。

首页简介之后首先显示「从观测到抓取」，分别展示 ZeroGrasp 和 SAM3＋RGB-D点云＋GraspGenX 两条主线，随后显示「研究版本与进度」；版本树在左侧从下往上展示抓取管线的继承关系，右侧汇总待办。点击节点进入独立详情页查看技术改动、评测结果、参考文献和媒体。所有详情页左侧提供本页标题目录，正文独立滚动。首页不嵌入演示视频和详细结果对照；成果页汇总 200 例同场景对照、失败分布、三条管线执行视频与 CLARO 固定挡物配对结果。

## 从外网通过 SSH 打开

Windows 上可将 [open-claro-arx.cmd](部署/open-claro-arx.cmd) 下载到本机并双击。脚本自动获取可用的本地端口，通过 SSH 转发到服务器的 8786 端口，探活通过后打开默认浏览器。浏览期间保持命令窗口运行。

在浏览器所在电脑的本地终端运行下面的命令。沿用已能连接服务器的 SSH 账号、地址和代理或跳板配置。

```bash
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:28786:127.0.0.1:8786 zhaoyechong@10.201.35.208
```

保持 SSH 会话运行，在本地浏览器打开 [127.0.0.1:28786](http://127.0.0.1:28786/)。左侧端口 28786 属于本地电脑，右侧端口 8786 属于服务器。

## 未来升级计划

首页的「未来升级计划」表格与 `/roadmap/` 详情页共同读取 `../../ARX-可达性地图/docs/未来改进计划.md`，来源在 `内容/网站.json` 的 `roadmap.source` 中登记。维护该 Markdown 后重新运行 `npm run build`，首页和详情页会一起更新；这些计划不作为已经完成的技术版本加入版本树。

首张 Markdown 表格用于首页进度列表，正文用于详情页。当前支持固定高度结果、七关节离线方案、位姿修正分析及 GraspCL 新库对照的站内详情链接，相关原文可下载；附件只在点击时加载。未来新增方向继续在同一份计划中登记目标、状态和验证方法。

## 实验主页、内部版本与批次

每个研究方向的主页保留在 `/iterations/<实验标识>/`，展示目标、可折叠的内部版本树、方案结果和运行批次。内部版本详情为 `/iterations/<实验标识>/versions/V1/`，批次记录位于对应版本的 `batches/<批次标识>/`。

内部设置与批次登记放在 `内容/experiments.json`，由 `experiments.mjs` 校验和生成。代号依次为V1至Vn（删除版本后保留编号空缺）。只有用户明确要求新开迭代时才新增节点，并在`authorization`中保存要求；界面、文字、小修和重复运行都不增加版本。重复运行只追加批次。构建不扫描输出目录来推断或创建版本。

“可达性改进”位于ZeroGrasp＋cuRobo主线下，V1 GraspCL、V2固定45.2 cm高度、V3升降联合规划和V5先升降后固定高度抓取是并列方案，`parent`均为空。“遮挡情况处理”的V1为CLARO。MPC标为已封存，放在单独入口中。

V3升降与右臂联合规划已按用户要求封存，树上用灰色节点及“已封存”标记，链接仍可进入原页。已封存实验及内部版本的详情页和批次页使用独立暖色卡片展示归档原因，原有实验内容默认折叠；点击目录或打开章节链接会自动展开并定位。新增V5“先升降、固定高度抓取”，当前只有方案说明，执行与抓取结果待验证。V5与其余方案保持并列；原生结果刷新脚本仅维护V2和V3，不重写实验主页或清除归档状态。

原`graspcl`、`lift452`、`joint7`、`claro`网址通过`experimentOwner`和`experimentVersion`关联到新的版本详情；原内容、流程、媒体和待办标识继续使用。历史阶段记录单独展示，不自动升级为迭代版本。主页待办汇总将原标识合并到所属实验，并提供具体版本的链接。

## 增加一个实验方向

1. 按用户明确提出的实验方向，在 `内容/迭代/` 写一份 Markdown，包含目标、设置、结果和参考文献。
2. 在 `内容/网站.json` 的 `versions` 中添加一条登记。给它一个唯一的 `id`，在 `parent` 填上一版的 `id`，并在 `file` 填 Markdown 文件名。
3. 在 `内容/experiments.json` 手工登记对应的V1、用户要求、设置和批次。
4. 在网站目录运行 `npm run build`。首页的节点与连线、实验主页、内部版本和批次页面会随构建一起更新。

下面的登记示例表示从ZeroGrasp主线分出的新实验方向。把 `type` 设为 `main` 可登记主线，设为 `experiment` 可登记实验方向。支持多个并列根节点：每个根节点都设 `parent=null`、`type=main`，在版本树同一底层展示，各自向上生长。已发布的 `id` 用于固定网址。

```json
{
  "id": "pose-refinement",
  "parent": "baseline",
  "type": "experiment",
  "title": "抓取位姿修正",
  "date": "2026-11-22",
  "status": "方案阶段",
  "summary": "评估局部位姿修正对可达性和实际抓取的影响。",
  "file": "pose-refinement.md"
}
```

`shortTitle` 和 `metric` 可选，分别指定树节点的短标题和已验收结果。单个版本内部的阶段记录可以加到 `records`，用 `parent` 指向所属版本。阶段页从版本详情进入，例如 CLARO 下的 `/iterations/v0.4/`。

当前根节点为 `baseline` 和 `sam3-graspgenx`。旧 `graspgen` 实验版本已按用户要求移除；原条目、网页说明和媒体映射保存在 `数据/版本归档/20261122_GraspGenX实验/`，冻结原始结果仍位于 ManiSkill，不向新主线继承实验成绩。新主线工作目录为 `../../ARX-SAM3-GraspGenX/`，当前是工作区与接口规划阶段，尚未完成全链路联调。

版本也可登记 `gallery`，指向 `内容/` 中的实验图集 JSON，并在正文用 `[[实验图集]]` 放置可点击拼图。当前十场景组件与场景图集均在新标签页打开原图，原页保留阅读位置；只加载缩略拼图，点击后才加载对应大图。图集的 `assets` 与场景来源单独登记，图片内容散列用于缓存。45.2 cm 实验由 `工具/汇总45厘米高度实验.py` 只读统计、核验和生成截图，`工具/发布45厘米实验版本.py` 在完整核验通过后登记版本和结果；两者均不启动仿真或重抓。

图片和视频在 `assets` 中登记时以 CLARO 的 `docs/` 为源目录，在 `benchmarkAssets` 中登记时以同级项目 `ManiSkill/` 为源目录。然后在 Markdown 中引用 `/media/文件名`。指向本站 MP4 的独立链接段落会显示播放器。

## 实验配置与核查

`/configuration/`是入口列表，包含200个评测场景、夹爪配置、可达范围检查三个详情页。TCP位置与碰撞球放在夹爪配置中，末端核查、前方地图和高度比较放在可达范围检查中。

在`内容/网站.json`的`configurationRecords`中登记标题、摘要和原文。单篇使用`file`，组合页用`sections`列出各篇原文。构建时生成`/configuration/<id>/`和Markdown下载；旧`/configuration/#原标识`会跳转到所属详情页。

V2和V3的当前页面只展示ZeroGrasp＋cuRobo。用`python3 tools/refresh-reachability-pages.py`从已核验汇总中提取原生管线，生成正文及单管线统计，再运行`npm run build`。生成器只更新现有页面与批次，版本数量保持不变。

## 待办事项

在版本详情页的待办栏输入内容并添加。勾选可标记完成，取消勾选可恢复为待办。每条待办旁的「删除」可移除该条。桌面端待办栏固定在右侧，窄屏时通过顶部按钮展开。首页按版本汇总未完成事项，点击版本名称可回到清单。后续登记的版本会自动获得待办区和汇总入口。

有权访问网站的访客共用同一份清单。待办保存在网站目录的 `resources/state/待办.sqlite`，构建页面与重启服务时沿用。待办服务使用 Node.js 22.13 或更新版本内置的 SQLite。

推送前运行`node tools/todo_snapshot.mjs export`，将全部待办、完成状态和编号导出到随Git保存的`resources/state/todos.snapshot.json`。新部署首次创建数据库时自动载入该快照，已有数据库不因重启而覆盖。迁移已有网站时，停服务后运行`node tools/todo_snapshot.mjs restore --replace`，原数据库会先备份到`resources/state/backups/`，随后恢复快照并核对结果。

## 场景图集

「配置与核查」中的场景图集展示独立随机生成的200个场景，采用头部主相机RGB截图，覆盖40类、80个物体型号。摆放在预先登记的物理区域内随机采样，构造阶段不使用IK结果；200例完成并散列冻结后再做事后诊断。每种布局以8列5行拼图展示，各40例。点击单格会在新标签页打开对应大图。

图片由`tools/build-scene-gallery.py`读取`ARX-SAM3-GraspGenX/configs/scene_dataset.json`指向的已核验场景生成，用同级ManiSkill虚拟环境的Python执行，再运行`npm run build`更新网站。脚本逐例核对截图与场景的文件散列。图集登记保存在`内容/场景图集.json`，派生图片保存在`内容/资源/scene-gallery/`；原中文脚本入口转调此脚本。

缩略图与大图均以黄色可见轮廓、指示线和中文名称标出目标。标注读取与RGB对齐的仿真目标实例掩码`target_gt.png`，只描绘可见区域的外轮廓；缩略图单独绘制标注，保留可读字号。原始数据集图片保持原样。

五张拼图使用浏览器延迟加载，大图在点击后加载。图片文件名含内容散列，可长期缓存。常规静态文件使用 ETag 校验缓存。

## 服务

使用 `claro-arx-progress.service` 用户单元。该用户启用了 linger，主机启动时会拉起服务。进程异常退出时由 systemd 自动重启。网站接收来自服务器本机和同网段私有 IPv4 客户端的连接。

```bash
systemctl --user status claro-arx-progress.service
journalctl --user -u claro-arx-progress.service -n 30
```

本机访问 `http://127.0.0.1:8786/`。服务单元源文件位于 `部署/`。

中文字形使用 Noto Sans CJK SC 的子集，按 SIL Open Font License 1.1 分发。 [字体许可](页面/notosc-OFL.txt)

## 论文调研与方法

导航中的「论文调研」支持按模块、接入状态和关键词查找。每篇论文的具体方法保存在 `内容/论文调研/` 的独立 Markdown 中，通过 `论文目录.json` 登记标题、作者、年份、原文链接、所属模块及关联版本。构建后生成 `/papers/` 和 `/papers/<id>/`，关联版本页自动显示方法页入口。

增加记录时，新增 Markdown 和对应登记项，再运行 `npm run build`。论文方法页同时提供 Markdown 下载。

各版本主页的「参考文献与方法」统一链接到站内 `/papers/<id>/` 论文详情页。新增引用时先登记对应论文页面；原论文、官方文档与代码仓库链接集中放在论文详情页。

每篇方法记录包含「主要方法」与架构图，说明核心思路、关键模块和数据流。当前四张架构图为根据原论文绘制的 SVG，点击可打开矢量原图；文件在 `内容/资源/论文架构图/`，用 `../../ManiSkill/.venv/bin/python 工具/生成论文架构图.py` 重新生成。生成器通过 fontTools 将 Noto Sans CJK 文字转为矢量路径，显示时不依赖客户端字体，并将正文新增用字补进网站字体子集。原论文流程与本项目 ARX 适配分别记录。

版本可选配交互流程图：在 `内容/网站.json` 的版本条目中设置 `workflow`，指向 `内容/流程/` 中的登记文件；该文件定义步骤、分支、节点位置、连线和对应 Markdown，版本正文用 `[[流程卡片]]` 放置流程。全部节点位于同一张 React Flow 画布，点击卡片弹出对应步骤详情，关闭后保留画布位置。详情里也可打开 `/iterations/版本/steps/步骤/` 独立页面。支持拖动空白区域、缩放、全图与全屏查看。

采用 [React Flow](https://reactflow.dev/learn/customization/custom-nodes) 的自定义节点，避免拖动事件吞掉点击；节点保留原生链接，支持新标签页打开。正文继续使用 Markdown。CLARO 的步骤文件在 `内容/流程/CLARO步骤/`，新增步骤或后续版本流程无需改写组件。

React、React Flow 与样式由 esbuild 在本地打包，版本由 `package-lock.json` 锁定，不请求 CDN。进入流程图区时才加载组件和登记，点击节点后才加载正文与该步骤媒体。组件文件名含内容散列，支持 gzip 传输及长期缓存。JavaScript 未启用或组件加载失败时，保留同一张可点击的 SVG 流程图。开发依赖需安装后再运行 `npm run build`。

CLARO 另保留可放大的矢量总览，用 `../../curobo/.venv/bin/python 工具/生成CLARO流程图.py` 生成。网页中的蓝色视觉验证路线、金色固定挡物实测分支和待接入模块分别标注；不将后续离线定位计入原实际成功率。

用户已要求删除底盘联合规划V4及其专用代码、结果和入口。V5编号与地址保留，删除后的编号空缺不重排、不复用。
