## 本版进度

已建立V7，承接V4的底盘、升降与双臂抓取链路。ZeroGrasp后处理源码已核对，下一步实现ARX适配并进行保存候选的离线比较。当前新增物理测试0次。

## 要解决什么问题

GraspGenX在69份已有观测中，每份生成944至6128个候选，中位数2240个。有些抓法彼此很接近，也有些抓法会碰到周围物体，或夹持区域里没有目标。V7要把这些候选先处理一遍，再交给cuRobo。

目标是保住能抓成功的抓法，同时减少重复检查，缩短“后处理＋规划”的总耗时。

## 本版链路

头部RGB-D → SAM3 → RaySt3R点云 → GraspGenX候选 → 碰撞与空抓筛选 → NMS去重 → 双臂cuRobo → 抓取。

宽度和切入深度修正单独作为一组比较，先核对ARX夹爪几何与执行接口，再加入测试。

## 准备比较哪些方案

| 方案 | 怎么处理候选 | 当前进度 |
| --- | --- | --- |
| 原候选对照 | 按GraspGenX原分数交给cuRobo | 已有原始候选 |
| 仅NMS去重 | 相似抓法只保留评分更高的代表 | 待离线测试 |
| 几何筛选＋NMS | 先去掉局部碰撞和空抓候选，再去重 | 待ARX几何适配 |
| 宽度／深度修正＋筛选＋NMS | 估算合适开度和切入深度，重新检查碰撞，再去重 | 待坐标与执行接口核验 |

所有方案使用相同的共享内存交接、一次解码和后台保存，分别记录新增后处理的耗时。

## 如何借用ZeroGrasp的方法

NMS先采用ZeroGrasp的参考设置：位置相差3厘米以内、朝向相近的抓法做去重，朝向阈值为30°。这是比较两个抓法是否相似，不会把抓姿旋转30°。每个被合并的候选都会记录它对应的保留候选。

碰撞与空抓筛选沿用ZeroGrasp“把点云变换到夹爪内部检查”的方法，夹爪区域改用当前ARX几何。ZeroGrasp原检测器的固定夹爪尺寸、GraspGenX的虚拟原点和当前TCP43先做统一，再核对左右手指交换是否真的是等价抓法。

近桌检查继续使用V2的指尖余量：最前端10毫米允许最多2毫米桌面接触。最终的关节限位、整臂碰撞和运动路径继续由双臂cuRobo检查。

## 怎样判断有没有效果

| 要看什么 | 具体记录 |
| --- | --- |
| 候选减少多少 | 原候选、碰撞筛选后、空抓筛选后、NMS后的数量 |
| 有没有误删好抓法 | 检查历史成功抓法是否保留，被合并后是否有可执行的替代候选 |
| 规划实际少做了多少工作 | IK查询数、轨迹规划调用数及规划耗时 |
| 总体有没有更快 | 后处理与规划合计的中位数、P90 |
| 抓取效果是否保住 | 相同场景的规划成功率、实际抓取成功率 |

先比较已有69份有效候选；后续物理对照沿用74例范围，包含5例共同站位失败。25例SAM3最终失败剔除，原中断1例单列。
