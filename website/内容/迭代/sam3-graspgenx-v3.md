## 本版改动

V2固定使用右臂。V3让同一组GraspGenX候选分别交给左右臂检查，选一条能完成抓取的手臂执行，另一条臂留在原位。

| 环节 | V2 | V3 |
| --- | --- | --- |
| 感知与候选 | 头部SAM3、RaySt3R、GraspGenX | 沿用同一链路 |
| 规划手臂 | 右臂六轴 | 左右臂分别规划 |
| 抓姿选择 | 第一条可执行原生候选 | 比较两臂可执行候选的原生排名；同一抓姿选关节位移较小的一侧 |
| 停放臂避碰 | 固定右臂执行 | 将另一条臂的实测原始碰撞网格加入规划场景 |
| 接触与记录 | 右臂末端、右侧双指 | 全部绑定本次选中臂，记录两侧规划结果 |

## 从观测到抓取

[[流程卡片]]

头部RGB-D → SAM3目标掩码 → RaySt3R点云 → GraspGenX原生抓姿 → 左右臂各自检查IK、碰撞与完整轨迹 → 选择执行臂 → 接近、闭合、抬升与保持。

每个目标执行一次选定臂的抓取。选臂发生在实际运动之前，闭合后按该臂实测手指状态重新检查抬升路径。

初态中右爪张开、左爪接近闭合。两侧规划都使用每指44毫米的张开状态，并预检原地张开过程中的目标、桌面和停放臂碰撞。选定后先实际张开夹爪、确认开度，再开始手臂运动。

## 双臂候选交替搜索优化

这项优化属于V3建立的双臂选择模块。验证复用了V6保存的观测、机器人状态和候选，完成19次纯规划请求；输入共5组，来自4个场景。

本次优化针对双臂规划中的等待时间。V6稀疏香蕉场景中，右臂检查3320个候选耗时444.78秒，左臂随后检查第一个候选就通过，整次首次规划耗时449.77秒。

### 搜索怎样调整

| 环节 | 原搜索 | 交替搜索 |
| --- | --- | --- |
| 搜索顺序 | 先完成右臂搜索，再开始左臂 | 右臂检查一批，左臂检查一批，再继续下一批 |
| 每批数量 | 一次请求可遍历完整候选池 | 首轮每臂最多16个，之后每批最多64个 |
| 搜索进度 | 每只手只接收一次候选池 | 各臂保存游标，从上次停下的候选继续 |
| 找到可执行候选后 | 限制后搜索手臂的候选前缀 | 两臂都受当前最佳原始名次约束，仍检查同名次候选 |
| 选择结果 | 原始候选名次优先，同名次比较关节位移，再优先右臂 | 沿用同一规则 |
| 候选交接 | 一次解码，双臂共享对象 | 保持一次解码，每批仅建立共享对象引用的列表视图 |

例如两臂都尚未找到解时，先检查右臂第1–16个候选，再检查左臂第1–16个。若左臂第1个候选通过，右臂此前已检查过同名次，便可结束比较。若两臂都没有通过，则分别从第17个继续，之后每批扩大为64个，以减少两臂状态重绑定次数。只剩一臂需要继续时，直接检查其剩余竞争前缀。

每个窗口都调用现有单臂规划器，保留抓取终点、预抓取与抬升终点、完整路径和局部接近检查。各臂开爪检查仍沿用原实现，碰撞模型保持每臂871球、TCP43和V2指尖规则。
